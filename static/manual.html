1. How the page is laid out

Narrative is one scrolling page divided into stacked cards. Top to bottom, here's the whole thing (rendered live with the actual app's CSS — what you see below is exactly what the app paints):

Voice and Library live in dialogs opened from the hero icons rather than as in-page cards. That keeps the text window dominant on every viewport — the manuscript is the work, and Narrative gets out of its way.

Each card is independent — you can keep listening to one clip while you paste, generate, or rearrange another. The hero icons (🎤 Voice / 📚 Library / ⚙ Settings) are the only chrome outside the text-listen-status flow.

Desktop drawer behavior. At ≥1024px viewports, Voice and Library slide in as right-side drawers (text content shifts left, drawers don't cover it). When you open BOTH at once, they stack: the most recently clicked one is "active" and gets the full content area; the other shows its content below filling the remaining space. The one not at the top has an accent border + ↑ chevron on its header — tap it to swap which drawer is on top.

2. Getting text in

The text card has three link-style actions in its header: Clear, Import ▾, and (context-dependent) Save text / Edit text. Everything you'd reach for — a single file, a URL, a GitHub repo, a Scrivener bundle, an Obsidian vault — lives inside the Import menu, so the header stays uncluttered as more sources land.

Action What it does
Clear Empties the textarea + decouples from any loaded clip. Use it when you're done with one piece and want to start a new one without refreshing.
Import ▾ Opens a small menu with one entry per manuscript source. See the next table for each option's behavior.
Save text (Only visible when a clip is loaded.) Writes any edits in the textarea back into the currently-loaded clip in the library. If the number of sentences changed, an auto-regen kicks off so the audio matches the new text. Typo fixes that don't change sentence count save instantly with no resynthesis.
Edit text (Only visible while you're in the reading view.) Hides the reading view, shows the textarea with the clip's full text ready to edit. Save text writes it back; Generate creates a new clip instead.

Import sources

Each entry in the Import menu has a one-line subtitle so a first-time tester knows what Scrivener / Obsidian even are before clicking — Upload says "PDF, EPUB, DOCX, TXT, MD — up to 25 MB", GitHub says "Browse a repo and pick chapters", etc. Single-document sources drop straight into the textarea; multi-document sources (GitHub, Scrivener, Obsidian) open a picker so you choose which chapters to import. Picking many builds a chapter queue — pre-synthesized, auto-advancing — that lets you walk through a whole project without touching the app between chapters.

New to Narrative? Land on an empty library with nothing typed and you'll see a "Get started" card with three big clickable starters — paste a URL, upload a file, browse a GitHub repo. Auto-hides the moment you type or save your first clip.

Background queue — synthesize silently while you work

Two ways into the silent / background pipeline. Both feed the same persistent queue, which you can reorder and add to at any time.

  • "Background — don't auto-play" checkbox in the multi-pick import picker (GitHub / Scrivener / Obsidian). Tick it before clicking Use selected and every chapter lands in the queue silently.
  • "Queue silently →" link button below the Generate / Download row. Type or paste text in the textarea, click the link, and that single piece lands at the back of the queue. The textarea clears so you can paste the next thing. Each enqueue snapshots the current voice / speed / volume — change the voice between queueings and only later jobs pick up the new pick.

While the queue runs, the chapter pill at the top shows "Background · Synthesizing [title] · 23/87 sentences · N more queued" with a pulsing accent dot. Generate is disabled (the textarea is yours to use for the next queue item); Cancel × on the pill aborts the in-flight chapter and drains the rest of the queue.

Below the pill, a queue panel shows the currently-synthesizing job + the pending list. The in-flight row carries a live "elapsed 0:45 · ~0:12 left" clock — the ETA only appears once enough sentences have completed for the per-sentence rate to settle, so the first few seconds avoid wildly-wrong estimates. Each pending row has a ⋮⋮ drag handle (drag to reorder — bring an item to the top by dragging it above the others) and a × remove button. The current job is locked at the top so you can't drag or drop it mid-synthesis (use Cancel × on the pill to kill the whole queue).

The queue panel's footer carries a "Recent repos:" chip row covering up to your last five GitHub projects — one click to round-trip back into a different repo's picker without re-pasting a URL. Mid-queue mid-flow: "I forgot chapter 4 from the other book" is one chip click + three checkboxes away.

Build-up workflow: Paste chapter 1 → Queue silently → Paste chapter 2 → Queue silently → discover you want chapter 5 to come next → paste it → Queue silently → drag chapter 5 to the top of the queue panel. Walk away. Come back to a populated library in the order you wanted.

Auto-retry + failures banner. Every failed chapter gets one automatic retry after a 1.5-second cooldown — most failures are transient (network blip, server cold start) and the retry recovers silently. Chapters that fail both attempts surface in a banner after the queue finishes, with the actual chapter titles + a one-click Retry failed button (re-runs the queue with just those chapters — original chapter data stays in memory, no re-fetch needed) and a View log button that jumps straight into the in-app debug log so you can see per-chapter HTTP / SSE errors + the sentence index where synthesis broke. Beats "see console" when something actually went wrong.

Empty-text guard. When a multi-file import produces empty text after extraction (e.g. a TOC.md that's just nav links, or an image-only chapter), the chapter is skipped before it ever enters the queue. The status bar tells you how many were skipped ("32 fetched, 3 skipped — see Settings → View debug log"); the debug log has per-file detail. Beats a confusing "no audio in result" failure deep into the synthesis pass.

Open Import → GitHub Gist and paste any of:

Background queue, debug log, OAuth, GHE

Things to wire yourself once and then reuse:

3. Choosing a voice

Voice picker

The dropdown lists every installed voice, grouped by engine:

  • Neural (high quality) — Piper voices, ~30–130 MB each. Sound natural.
  • System voices — your OS's built-in TTS (SAPI on Windows). Always available, lower quality.

Multi-speaker voices like LibriTTS ship 904 distinct speakers in one model — when one of those is selected, a Speaker picker appears below with options Speaker 0 through Speaker N-1. A small ▶ button next to the speaker dropdown plays a preview of the selected speaker.

Browse voices

Tap Browse voices to open the catalog: ~160 voices across ~30 languages. Each row has:

  • ★ Favorite — tap to star. Starred voices float to the top of the main voice picker in a "★ Favorites" group.
  • ▶ Preview — proxies the official sample MP3 from HuggingFace, plays inline.
  • Install — streams the .onnx + .onnx.json over SSE with a live percentage in the button label (0% → 100% → Installed). Lands directly in your voices/ folder.
  • × Remove — appears for installed voices only; deletes both files and frees disk.

Above the catalog, three filter chips: ★ Favorites only (N), Installed only (N), and Commercial only (N) (v218). The chips combine — turning on Commercial + Installed gives you the shortlist you can publish with, today, without scrolling. All three reset when you close and reopen the dialog so first-time browsing always sees the full catalog. The search input filters by language, country, or name.

Commercial-use badges

Each row carries a small license badge next to the voice name. Commercial ✓ means the underlying dataset license permits selling audio you generate, with attribution. Non-commercial means the license blocks redistribution for profit — fine for personal use, not for publishing an audiobook.

Hover (or long-press on touch) the badge to see the dataset, the exact license, and the attribution string you'd put in audiobook credits.

Why this matters. Piper voices are trained on public datasets, and the dataset's license follows the voice through every step. Lessac — the base voice many Piper models are finetuned from — is licensed under Blizzard Challenge 2013, which is research-only. Anything finetuned from Lessac (including Amy, Alan, and Arctic) inherits that restriction. Currently cleared for commercial use: LibriTTS, LibriTTS-R, VCTK (109 British speakers), and Jenny. If you intend to publish what you generate, stick to those.

Voices that haven't been audited yet default to non-commercial — safer than promising the opposite. Future Narrative versions will flip more voices to green as the audit catches up.

Speed & volume

Two sliders affect synthesis only — they get baked into the generated audio. Speed (80-300, default 180 wpm) controls the engine's word rate; 180 sits in the audiobook- narration sweet spot. Volume (0-100%, default 100%) is the sample multiplier; most authors leave it alone and adjust on the device side. For changing playback speed on an existing clip, use the 1× chip on the player instead (see Section 4) — that doesn't re-encode anything.

The Defaults link in the voice card header resets Speed to 180 and Volume to 100% in one click. Voice and speaker stay as-is so you don't lose your pick when backing out of slider experiments.

Saved presets

Found a voice + speed + volume combo you like? Hit Save preset, name it (e.g. "Audiobook narrator"), and a chip appears under the voice picker. Tap the chip to re-apply all four settings. Long-press / × deletes.

Characters (Author mode)

Assign different voices to different characters in your draft. See Author mode below.

4. The player

Above the native browser audio control, there's a row of action chips. Left to right:

On desktop and landscape tablet (≥1024px), the chip row floats at the top center of the page as a frosted backdrop-blur bar — always reachable without scrolling. When a right-side drawer (Voice or Library) is open, the bar slides left so it stays centered in the visible content area. Mini-player (sticky top bar when the main player scrolls off) hides the floating chips while it's showing so the top doesn't get two competing control bars.

↶ — Skip-back / ↷ — Skip-forward

Tap to rewind / jump ahead by the configured interval. "I zoned out for a moment" recovery — different from the lock-screen prev/next which jump a whole sentence. The skip distance is configurable in Settings → Skip interval (2 / 5 / 10 / 15 / 30 s); the chip labels update to match. Smaller for re-listening tricky sentences; larger for skipping past sections you already heard.

🔖 Bookmark

Drops a bookmark at the current audio position. The chip's label updates to show the count (🔖 Bookmark · 3), and a list appears under the player:

  • Tap the time on the left to jump there and play.
  • Tap the note field, type a reminder, press Enter or click away to save.
  • Bookmarks live with the clip in the library (export/import too).
  • Auto-regen on save-text preserves bookmarks even if the audio is rebuilt.

A↔B loop

Re-listen to a tricky passage. Cycles through four states on tap:

  1. A↔B — idle.
  2. A 1:23 — A captured at current time, waiting for B.
  3. ↻ 1:23–2:45 (accent background) — both set, looping. Playback resets to A whenever it crosses B.
  4. Tap once more to clear.
Play forward between taps. The 2nd tap takes the current playback position as B. If the playhead hasn't moved since you marked A (e.g. you were paused), the chip stays at A 1:23 and the status line nudges you to play or seek before tapping again. Loading a different clip clears the loop bounds (they belonged to a different audio track).

💤 Sleep timer

Cycles Off → 15 → 30 → 45 → 60 min → End of chapter / End of clip. For the minute presets, audio fades over 5 seconds and pauses gracefully when the timer expires — the saved resume position lands at the exact moment of fade-out, so the next morning the clip starts where you fell asleep.

The End of chapter / End of clip mode (Libby-style) stops at the next natural narrative boundary instead of guessing minutes. With a chapter queue active the label reads "Chapter end"; without one it reads "Clip end". Pre-synth of the next chapter is suppressed while this mode is armed (no point synthesizing audio you won't hear).

📝 Notes

Opens a focused dialog tied to the currently-loaded clip — clip title at the top, a big multi-line textarea below. Use it for free-form thoughts while listening: edits to revisit, voice direction, continuity reminders, beat-sheet notes. Closing the dialog saves automatically (no Save button to remember mid- thought); cards pick up a small 📝 Notes indicator under their meta line so you can see at a glance which clips have notes attached. The same field is also editable from ✎ Edit → Notes, and it travels through Export / Import along with bookmarks and tags.

Distinct from the one-line Note field on ✎ Edit: that one acts as a card subtitle (chapter number, author, status); Notes is a free-form scratchpad with no card display, so you can write at length without cluttering the library.

📝 + 🔖 in practice — the author editing workflow

Bookmarks and Notes coexist because they serve different moments in a revision pass. Here's how authors actually use both during a listen-through:

MomentToolWhy
You're listening, hear a typo / wrong comma / weird emphasis 🔖 Bookmark One tap, marks the exact second, no flow break. Optional one-line note: "fix comma."
A sentence rhythm feels off and you want to revisit 🔖 Bookmark + 1-line note "rewrite — too breathless" attached to the timestamp lets you find it later by searching the bookmark list, not by re-scrubbing.
Step back after a chapter, think about pacing or theme 📝 Notes Not tied to one moment. Multi-paragraph reflection on the whole chapter. "Middle drags. Cassian's interiority disappears around the felling scene."
Continuity check across multiple chapters 📝 Notes "She's blue-eyed in ch 2, brown in ch 7 — fix one or both." Lives on the relevant clip; no need for a single moment.
Pasting external feedback (editor letter, beta-reader email) 📝 Notes Long-form reference material parks here so you can listen + read in the same view.
Reviewer comments tied to specific moments ("the dialogue at 4:15 feels expository") 📝 Notes (today) → 📝 Notes + ⏱ inline timestamps (future) Today: paste the comment as prose. Coming: type [4:15] inside Notes and it'll render as a clickable seek-link.

The rule of thumb: bookmarks during the listen (in-flow spot fixes), notes during the review (stepping back). Neither is the right tool for both — that's why both exist.

Playback speed (1×)

Cycles 1× → 1.25× → 1.5× → 1.75× → 2× → 0.75× → 1×. Affects playback only, not stored audio. Choice is persisted per browser. Reapplied automatically when the audio source changes (per-sentence streaming, clip switch).

At any speed other than 1× the player time row appends "· 1h 50m left" next to the duration — your actual wall-clock remaining at the chosen speed. The speed chip's tooltip carries the full breakdown ("Speed 1.5× · 3h 24m → 2h 16m at this speed"), useful when planning whether you'll finish a chapter before your stop.

5. Reading view

Once a clip is playing, the textarea swaps for the reading view: the source text rendered as clickable sentence spans. The active sentence is highlighted; played sentences fade slightly so you can see your progress.

  • Tap a sentence to seek there and keep playing.
  • The active sentence stays in view inside the reading-view box (the box has its own internal scroll, so it never yanks the rest of the page around).
  • Tap Edit text in the text-card header to go back to the textarea for edits.
On phone, the lock-screen prev/next buttons jump by whole sentences — useful when you missed context, not just a word. The on-screen ↶ 5s is for the missed-a-word case.

6. Book view

Tap the 📖 Book view link in the text card actions row (next to ▶ Audio view) to flip the reading view into a paginated, two-page-spread book layout. Same clip, same audio, same click-to-seek — different visual model. Toggle back with the ▶ Audio view link in the same row.

Pagination is real: pages are computed by an off-screen measurement pass and break on sentence boundaries so prose never gets cut mid-word. Each spread shows the cover (left) + first text page on spread 1, then two text pages per spread after that. Mobile collapses to one page per spread.

Navigation

  • ‹ / › in the nav row → previous / next spread.
  • ← / → keys → same.
  • Swipe horizontally on the spread (touch only) → page turn. Swipes that start on a sentence, image, or button don't trigger so click-to-seek and text selection still work.
  • Click the "Spread X of Y" indicator → it becomes a number input. Type a target spread, press Enter to jump.
  • Ctrl+F / Cmd+F while in book view → opens a find bar. Case-insensitive substring search; ‹ / › cycle matches; Enter advances; Esc closes. Each match jumps to the page containing it.
  • 📑 Contents button (visible only when chapters are detected) → opens a table of contents listing every chapter with its page number. Click a row to jump.
  • ↩ Return to current button appears whenever you've manually paged away from the spread containing the currently-narrating sentence. One click brings you back; subsequent karaoke flips resume.

Chapter awareness

Narrative tries to find chapter boundaries inside the clip's text using three heuristics: Markdown ATX headings (# Title / ## Title), explicit "Chapter N" / "Part Three" patterns, and bare Roman numerals as short standalone sentences. When chapters are detected:

  • The paginator forces a fresh page before each chapter (book convention).
  • A drop cap renders on the first letter of every chapter's opening page, not just page 1 of the clip.
  • The running header at the top of each page shows the current chapter's title. Pages before the first detected chapter (preamble) fall back to the clip title.
  • The 📑 Contents button shows; clicking it opens the chapter list.

Clips with no detectable chapter pattern still work — they render as a single section using the clip title for the running header.

Theme + text size (Settings)

Settings → Book view theme picks the typographic personality of the pages, independent of the app-wide Dark/Light theme:

  • Paperback (default): serif, single column, justified — classic novel look.
  • Magazine: sans-serif, two columns on desktop (one column on phones; two ~140px columns are unreadable). Inline images that fit within one column stay inside it; larger figures span the gutter.
  • Manuscript: monospace, looser line-height, left-aligned (not justified) — the typewritten-draft look.

Settings → Book view text size (Small / Medium / Large / X-Large = 14 / 16 / 18 / 20px) controls the body font size. Changing it re-paginates on the fly and anchors the new spread on the same sentence you were reading — no jumping forty pages because the page breaks shifted.

Bookmarks + highlights

  • 🔖 Bookmark (the chip in the hero strip) adds a bookmark at the playhead — same as in audio view. In book view, every bookmarked page gets a small accent- colored ribbon in the top-right corner. The two views share bookmarks: a bookmark made in audio view shows on the right page in book view, and vice versa. Tap a ribbon to remove the bookmark from that page — useful for clearing a clunky-paragraph mark you already fixed. Multiple bookmarks on the same page remove one tap at a time, oldest first.
  • Text highlights — drag-select any text inside a sentence (in book view OR audio view) and a small floating toolbar appears with three colors (yellow / pink / blue) + an × remove button. Click a color to save the highlight; × removes any highlight under the current selection. Esc dismisses the toolbar without saving. Highlights persist to the clip and show in both views. Multi-sentence selections aren't supported in v1 — the toolbar stays hidden if your selection crosses a sentence boundary.

🖨 Print

Click 🖨 Print in the nav row to print the entire clip as a stack of paperback-sized sheets (5.5 × 8.5 in, 0.5 in margins). Each page becomes its own printed sheet; the cover prints first; running headers, drop caps, and page numbers carry through. Override the page size in your browser's print dialog if you'd rather print US Letter / A4. Use the dialog's "Save as PDF" destination if you don't have a printer.

Page numbers are 1-indexed and live in the outer bottom corner of each page (left page → bottom-left, right page → bottom-right) — matching how printed books carry numbers at the outer corner where you'd thumb the page.

7. The library

Every clip you generate is auto-saved into a per-browser library (IndexedDB). Newest clips appear at the top by default.

🎉 First save. The first time a clip lands in your library, paper confetti rains down and a one-time tour banner appears at the top of the page: "This is your first clip. Tap ✎ Edit to add a cover, drag ⋮⋮ to reorder, tap 📝 to write notes." Both fire exactly once per device, exactly on the 0 → 1 transition (not on reloads with clips already on file). To see them again — or to replay any first-tap hint you dismissed by accident — open Settings → Replay onboarding tips → (§ 7). Confetti respects your OS-level prefers-reduced-motion setting and skips the animation if you've turned it on.

Cover art & page backdrop

Every clip carries a visual identity. By default it's a gradient tile derived from the title hash, but you can upload your own story-board art through ✎ Edit → Cover image. Uploaded images are resized to 256×256 (cover-fit, center crop) and JPEG-compressed at ~85% quality — about 20-30 KB each, so a 100-chapter library adds 2-3 MB total.

Once a cover is in place, two things happen across the UI:

  • Library card tint. The dominant color of the cover is sampled (Canvas down-sampling + RGB→HSL average) and applied as a soft ~12% wash across the matching card — Libby/Hoopla-style. Clips without an uploaded cover still get a wash from the title hash, so every card has its own color identity at a glance.
  • Page backdrop. When you load a clip with an uploaded cover, the image fades in as a heavily blurred + dimmed atmosphere behind the entire page (Libby's "you're inside this book" feel). Fades back out when you clear the textarea.

The cover ships in the library zip under covers/{clip.id}.jpg with the dominant color carried in the manifest entry, so Export → Import round-trips your full visual workspace. Removing a cover (✎ Edit → Remove cover) drops back to the gradient + hash-color fallback.

Voice provenance (v219+)

Every clip generated v219 and later carries a snapshot of which voice + license were in effect when its audio was rendered. Open ✎ Edit on a recent clip — you'll see a "Voice provenance" block with:

  • The voice name and (for multi-speaker models) the speaker id used.
  • The license name and the dataset the voice was trained on.
  • The exact attribution string you'd put in audiobook credits, video descriptions, or animation end-cards.
  • A green "Commercial ✓" or amber "Non-commercial" badge mirroring the catalog browser.
  • A Copy button that lifts the attribution string to your clipboard in one click.

Provenance is a snapshot, not a live lookup: even if Narrative's license audit later changes (a voice gets reclassified, an attribution string updates), the clip remembers what was true when it was generated. That's the right behavior — the audio you have on disk was made under those terms.

Provenance ships in the library zip and round-trips through Export → Import, so backups carry the credit information with them. Clips generated before v219 simply don't show the block — the Edit dialog handles the absence quietly. If you want provenance on an older clip, re-narrate it with the same voice and the new generation will capture it.

Sections

The list splits into two sections automatically:

  • CONTINUE LISTENING — clips with a saved resume position (you started but didn't finish). Always at the top so "where was I" is one tap.
  • OTHER CLIPS — everything else. Same sort + filter as the top section.

Both sections respect the active sort mode. If a clip plays to the end, it auto-moves down to Other Clips on next render.

Search + sort + filter

  • Search box matches title, source text, voice name, OR note text. Press Esc to clear.
  • Tag filter row appears above the library once any clip has tags. Click a tag chip to require it; click again to drop it; multiple chips compose AND. The count beside each tag reflects the post-search visible set.
  • Sort chip cycles Newest → Oldest → Longest → Shortest → Custom → Shuffle. Custom uses your drag-defined order; auto-switches on the first drag.
  • Hide played (in the library tools row) hides clips you've finished and reset. Becomes "Show all" when active. State persisted.

All bookmarks

Library tools also surface an All bookmarks button (shown once any clip has a bookmark). It opens a timeline of every bookmark across every clip — grouped by clip, sortable by recency / time-in-clip / clip title, filterable by note text or tag. Each row's Jump button loads the source clip and seeks to the bookmark. Built for authors revising a long manuscript: one place to triage every "fix this" note.

Drag to reorder

Tap and drag the ⋮⋮ handle on any card. Releasing flips the sort mode to Custom order and persists. Auto-advance plays through clips in the order you see them — so dragging chapters into reading order means the audiobook just works.

First time you see the library with 2+ clips, a one-shot accent tip appears above the list: "💡 Tip — drag the ⋮⋮ handle on any card to reorder." The tip auto-dismisses on your first successful drag (or via the × on the banner) and never returns.
Reordering inside Continue Listening reorders within that section. When a clip's resume position is cleared (manual ↺ reset or auto-advance to next), it drops down into Other Clips at the position you put it.

Auto-advance

When a clip ends, the next one in your chosen sort order starts automatically — with a 3-second breath between them. Status shows "Up next in 3s…".

If you tap a different clip or hit Clear during the gap, the queued load is cancelled.

Sync GitHub + Re-narrate outdated

Two library-tools-row buttons collaborate to keep GitHub-sourced clips fresh against upstream commits.

  • Sync GitHub walks every clip that carries a gitRef (set automatically when you imported it from a GitHub raw URL or the repo picker), groups them by repo + branch so one tree call covers many clips, and compares each clip's stored SHA against the current upstream SHA. Clips whose SHA has moved get flagged with an accent border + an "outdated" badge. Surfaces a status like "7 of 35 clips have newer commits on GitHub."
  • Re-narrate outdated (N) appears next to Sync GitHub the moment Sync flags anything. One click and every outdated clip gets re-fetched and re-queued in the background queue — title, tags, cover, bookmarks, and notes all survive untouched; only the source text + audio + SHA get replaced. The bookmarks ride through because the text is the same shape (you just want the new commit, not a redesign).
Sync needs a token (PAT or OAuth) with at least public-repo scope; private clips need repo. Without a token you'll see "Set a GitHub PAT in Settings before syncing" — see § 8.

Export / Import

Below the search:

  • Export — builds a zip containing every clip as MP3 plus a JSON manifest.json with all metadata (titles, one-line subtitles, free-form Notes scratchpads, voices, speakers, sentence offsets, resume positions, bookmarks, tags, covers, presets, library order, play mode). Downloads as narrative-library-YYYY-MM-DD.zip.
  • Import — pick a previously-exported zip. Clips with IDs that already exist are skipped (so re-imports are safe). Restores presets and custom order too.
The zip is a real PKZIP file — your phone's Files app can open it, you can extract individual MP3s with any zip tool, the manifest is human-readable JSON.

Character voices

Open Characters and add one row per character. For each: name, voice, and (if the chosen voice is multi- speaker like LibriTTS) a speaker ID.

When you hit Generate, Narrative scans your text sentence by sentence. Each sentence is routed to a character (or the main narrator voice) using this priority order:

  1. Explicit name in the sentence — "Welcome," said Sarah. → Sarah's voice. Definitive.
  2. Pronoun → declared gender — "How are you?" she asked. → the most-recently-named female character. Works as long as the character's Gender field (She / He / They) is set in the Characters dialog.
  3. Active speaker carry-forward — a sentence with a quote but no name and no pronoun continues the previous speaker. Long speeches split across multiple sentences inherit one voice.
  4. Last-named character fallback — if none of the above resolved, the most recently mentioned character takes attribution.
  5. Narrator — sentences with no quote use the main voice picker. Cursors above still update for the next dialogue sentence's benefit.

The three cursors (last-named, last-by-gender, active-speaker) all persist across paragraphs and sentences. Real prose names a character once early in a scene and refers to them by pronoun for paragraphs after — the segmenter remembers. Narration between dialogue sentences doesn't break the chain either: 

Llea drew a breath. "House Ashworth of Viciny," she said.
"I have a list of the noble families. I know where the gaps are."
She set both hands flat on the table.
  • Llea drew a breath. → narrator. Cursors updated: lastNamedChar = Llea, lastByGender.female = Llea.
  • "House Ashworth of Viciny," she said. → quote + female pronoun → Llea. activeSpeaker = Llea.
  • "I have a list of the noble families. I know where the gaps are." → two quote-bearing sentences with no name and no pronoun → active-speaker carry-forward → both Llea.
  • She set both hands flat on the table. → no quote → narrator.
If a line you expected to route through a character came out in the narrator's voice, the cause is usually that the character's name has never appeared in the text above that point — there's nothing for "she" to resolve to. Name the character once near the top of the scene and the rest of the scene picks up correctly.
If you assign two characters voices from different Piper models with different sample rates (e.g. one _low 16 kHz and one _high 22 kHz), the multi-voice synthesis will fail with a clear error in the status line. Pick voices from the same quality tier (all medium or all high) to mix cleanly.

Cross-device sync (v221+)

Settings → App → Sync library across devices ties your library to the Narrative server so you can edit on a desktop and listen on a phone without exporting/importing. Off by default. Flip on per device.

  1. On the device that should push: Settings → App → Sync library across devices → On. From now on, every saved clip pushes to the server in the background as you go.
  2. On the device that should pull: same toggle → On. Open the library — within ~30 seconds new clips fetched from the server appear with playable audio.

Under the toggle a status line reads "Sync on. Last pulled 2 min ago." Sync pulls run on library open and every 60 seconds while the app is foreground.

What's on the server: clip text, voice choice, bookmarks, notes, tags, cover, progress, character roster, voice presets, and the MP3 audio (one copy per unique synth — same text + voice dedups by content hash). What stays per-device: voice favorites, A↔B markers, current playback position in this session, debug log.

Audio re-use is the big win. When you re-narrate chapter_03 at your desk with Kokoro Heart, the resulting MP3 is stored on the server keyed by SHA. Your phone pulling that clip just downloads the finished file — no second synth, no Fly CPU burn, no watchdog timeouts. The same MP3 played from any device is bit-for-bit identical.

Conflict rule: if you save the same clip on two devices within the same minute, the last save wins. The losing device shows a quiet "Library was updated on another device; using the latest." status. In practice you rarely edit on two devices simultaneously, so this is almost never visible.
Privacy caveat: with sync on, your draft text and the synthesized audio do leave your machine — they live on the Narrative server until you delete the clip. Sync off keeps everything 100% local. The privacy guarantee from the landing page ("Your draft never leaves your machine") applies to sync-off mode only.

Maintenance warnings

When the server is about to restart for a deploy or other maintenance, a sticky amber banner appears at the top of the app with a short message and a countdown. The banner turns red and gently pulses once the maintenance window starts, then vanishes when it ends. Tap × to dismiss it for this session; a new window with a different start time will resurface it. Use a re-narrate that finishes before the start time, or pause and resume after — long synths get killed by deploys (5-minute grace, but a 9-minute chapter is still vulnerable).

9. Listening on your phone

Narrative is a Progressive Web App (PWA) — install it from the browser and it lives on your home screen, runs in the background, and surfaces play / pause / skip on the lock screen.

Install on iOS (iPhone / iPad)

  1. Open the Narrative URL in Safari (not Chrome — iOS only installs PWAs from Safari).
  2. Tap the Share button (square with an up-arrow).
  3. Scroll down and tap Add to Home Screen.
  4. Confirm the name → Add.

Install on Android

  1. Open the Narrative URL in Chrome.
  2. An "Install" prompt usually appears at the bottom — tap it.
  3. If you missed the prompt: ⋮ menu → Install app (or "Add to Home screen").

First-time API key

The first time you load the alpha, a prompt asks for an API key. Paste the key you received with the invite — it'll look like narrative-xxxx-xxxx-xxxx-xxxx. It's saved in your phone's localStorage and sent automatically forever after; you'll never see the prompt again unless you clear browser data.

Your key is unique to you. Each tester gets their own key so your library stays isolated from every other tester's. Don't share it — anyone with the key sees (and can edit) your library. If you want to use Narrative on more than one of your own devices, paste the same key on each. That's what makes cross-device sync land on the same library.
If you clear browser data and lose the key, ask the admin to mint you a new one. The library you'd built up under the old key stays on the server but becomes unreachable from the new key — practically a fresh start. Don't lose the key.
Admins only: troubleshooting the Tester keys form (mint / list / revoke) lives at /admin-troubleshooting.html. Bookmark it.

Onboarding with your key — step by step

First time on a device. Run this whenever the admin sends you a new key, or when you set up a second device of your own and want it on the same library.

  1. Open the URL the admin sent you — usually something like https://narrative-alpha.fly.dev. On a phone, use Safari (iOS) or Chrome (Android).
  2. A small browser dialog appears with the message "This Narrative server requires an API key. Paste your X-Narrative-Key value (set by the server admin):" and an input field. This is a native browser prompt (not a Narrative-styled dialog), so it'll look like every other prompt your browser shows.
  3. Paste the key exactly as the admin sent it (narrative-xxxx-xxxx-xxxx-xxxx). Don't add spaces, don't add quotes — just the bare string. Click OK.
  4. The app loads. No reload needed. You'll see the empty-library "Get started" tiles (or, if you're setting up a second device with sync on, your existing library).
  5. To confirm it stuck: refresh the page. The prompt should not reappear. The key is now saved in your browser's localStorage under the name narrative.apiKey and sent automatically on every request from now on.
  6. (Optional, for your own multi-device setup) Open Settings (⚙) → flip Sync library across devices to On. Repeat all six steps on every other device of yours using the same key. Same key on multiple devices → same library; see Walkthrough 6 in §11 for the full two-device flow.
If you typo the key: every request fails with an authentication error, and the prompt re-opens automatically on the next request. Paste the right key and click OK — no reload needed. The original prompt may have closed already; just try any action (open the library, browse voices) and the re-prompt fires.
If you dismiss the prompt without pasting (clicked Cancel, hit Escape, swiped the dialog away on mobile): nothing breaks — the app loads but every API call fails. Hit refresh, or trigger any action, and the prompt comes back. Paste then.
Switching to a new key (admin re-minted you because you lost the old one, or rotated for security): you need to clear the saved value first.
  • Easiest: in the browser console (F12), run localStorage.removeItem("narrative.apiKey") then refresh. Paste the new key at the prompt.
  • Mobile (no devtools): clear the site's cookies + site data. iOS Safari: Settings → Safari → Advanced → Website Data → search "narrative" → swipe delete. Android Chrome: app settings → Storage → Clear cache (NOT Clear storage — that wipes your local library too).
  • Either way, the next page load shows the prompt again.

Lock-screen + Bluetooth controls

Once a clip is playing, the lock screen shows the title, play / pause, and skip-prev / skip-next. The skip buttons jump a whole sentence, not a fixed time — so when you missed context, you hear the whole sentence again instead of landing mid-word.

On Bluetooth headphones the play / pause button and skip track buttons map to the same controls. Useful while driving, working out, or walking.

Background playback

Locking the phone, switching apps, even closing the browser UI to one tab — audio keeps playing. The current clip's progress saves automatically, so if the OS does eventually evict the tab, you can reopen Narrative and Continue Listening picks up where you left off.

If the connection drops

Clips already loaded keep playing — the audio is buffered on your device. Generating new clips needs network, so save the long ones at home and listen on the train.

Running Narrative on your own machine instead of using the hosted alpha? See DEPLOY.md for Fly.io deployment, and scripts/tunnel.py for sharing a local instance over a Cloudflare tunnel.

Workflow ideas

  • Audiobook a book chapter-by-chapter. If the book lives in one big file, paste it and the chapter detector queues each chapter automatically. If it lives across many files (Scrivener scenes, Obsidian notes, a GitHub manuscript repo), use the matching Import option and pick the chapters you want — same chapter queue, same pre-synth + auto-advance with 3-second breaths between chapters.
  • Listen to your own draft as it changes. Keep your manuscript in Scrivener / Obsidian / GitHub.   • Read articles you'll never read. Install the PWA on your phone, hit Import → Paste URL with a long-form article, generate, listen on the move. The Continue Listening shelf handles "I started this on my commute, finish on the train home."
  • Revise your own writing. Author mode on. Generate. Walk around. Tap 🔖 every time you hear something to fix; type quick notes when you stop. Back at your desk, tap each bookmark's time to re-hear it, fix the manuscript, Save text — auto-regen if sentence count changed — listen again. Repeat.
  • Stress-test dialogue. Author mode → add your characters with distinct LibriTTS speakers → Generate a chapter. If two characters' dialogue sounds the same in your own ears, your prose may be confusing them on the page too.

Where your data lives

  • Library (clips + bookmarks + notes) — IndexedDB audiable database in your browser. Per-browser-profile, per-origin.
  • Voice models — voices/*.onnx on the server machine.
  • Synthesis presets + library order + custom config — localStorage keys under narrative.*.
  • Uploaded files (PDFs, etc.) — extracted in memory on the server, never saved to disk.
Use Export regularly to back up everything as a single zip. The whole library state restores cleanly on any device.

11. Tester walkthroughs

Six numbered end-to-end runs. Each starts from a clean page load (or the closest a state-bearing app can get to one). Each step lists the expected screen / status / next click so a fresh tester knows what success looks like at every step.

Walkthrough 1 — URL fetch → chapter auto-split → background queue

Tests: URL extractor, chapter detector, picker, background queue, elapsed clock, library cards.

  1. On the empty library, the "Get started" empty- state card is visible with three starter buttons. Click Paste a URL.

Walkthrough 2 — GitHub OAuth → tree picker → Sync

Tests: OAuth, recent repos, branch picker, tree view, tri-state folder, ✓ imported, Sync GitHub, Re-narrate outdated.

Prereq: GitHub OAuth App registered (operator step — OAUTH_SETUP.md). Without that, skip step 1 and use a PAT in step 2's first Settings detour.

  1. Settings → GitHub section. The Sign in with GitHub button is enabled (or disabled with a tooltip if OAuth isn't configured — go set it up).
  2. Click Sign in. Browser navigates to github.com, authorize. You're back on Narrative — status reads "✓ Signed in with GitHub — token saved." Reopen Settings; the GitHub section now reads "Signed in as @yourhandle".

  7. Once done, open Import → GitHub again. The "Switch to:" chip row above the URL field now shows progit/progit2 as a recent. Open the picker again on progit; the files you just imported render dimmed with ✓ imported pills. Try Hide already imported.
  8. Close the picker. In the library, click Sync GitHub. Status reads "Syncing N clips across 1 repo…" then "All N clips up to date."
  9. (Optional — force a re-narrate) Pick any imported clip → ✎ Edit. The dialog shows a "From GitHub: book/…/foo.asc @ a1b2c3d" meta line. Close. Status now reads "1 of N clips have newer commits." A Re-narrate outdated (1) button appears next to Sync. Click it → the background queue panel opens with that clip mid-fetch. Walkthrough 5b — Book view end-to-end

Tests: pagination, chapter detection (drop caps, running headers, Contents dialog), themes (paperback / magazine / manuscript), font-size repagination, find + page-jump + swipe, bookmark ribbon, text highlights, print. Use the same Tom Sawyer clip from Walkthrough 1 — its 33 chapters exercise chapter-aware behaviors well.

  1. Library → open any chapter clip with at least 5,000 chars. Status shows playback ready. The reading view renders; sentences light up as audio plays.
  2. Click 📖 Book view in the text-card actions row. The view flips to a two-page spread (cover on left for the first spread). Indicator reads "Spread 1 of N". ‹ is disabled.
  3. Click ›. The spread advances. The currently-narrating sentence has a soft accent highlight. Confirm the running header at the top of each text page shows either the chapter title (when chapters detected) or the clip title (when not), and the page number sits in the outer bottom corner.
  4. Open Settings. Try Book view theme → Magazine: page body becomes sans-serif + two columns (on desktop ≥720px wide). Close Settings. Pagination has been re-run; you'll land on the spread covering the same sentence you were reading. Switch to Manuscript: monospace, looser lines, left-aligned. Switch back to Paperback.
  5. Settings → Book view text size → Large. Pages re-paginate; anchor sentence stays put. Indicator's total-spread count grows because each page now holds fewer sentences.
  6. Click the 📑 Contents button (visible only when chapters are detected). A dialog lists every chapter with its page number. Click any row. The spread jumps to that chapter. Drop cap on the chapter's opening letter; running header shows the chapter title.
  7. Click the "Spread X of Y" indicator. It becomes a number input. Type a number near the middle of the book (e.g. 10), press Enter. The spread jumps.
  8. Press Ctrl+F (Cmd+F on macOS). A find bar appears above the spread. Type a word you know is in the text. The count badge updates (e.g. "1 / 17"); the spread jumps to the first match. Press Enter or click ›. Next match. Esc closes the find bar.
  9. On a touch device (real phone, or DevTools mobile emulator with touch events on): swipe left across the spread. Page advances. Right swipe goes back. Quick taps on sentences still seek to the audio position.
  10. Hit play. While listening, press the 🔖 Bookmark chip. The book view re-renders; the page you were on shows a small accent ribbon at the top-right corner. Toggle to Audio view (▶ Audio view link), then back to Book view — the ribbon is still there.
  11. Drag-select a phrase inside any sentence. A floating toolbar appears above the selection with three colors + ×. Click yellow. The selected text gets a yellow background. Drag-select another phrase. Pink. Drag again on the yellow phrase, click ×. The yellow highlight is removed. Toggle to Audio view; the pink highlight is visible there too (same shared rendering).
  12. Back in Book view, click 🖨 Print. The native browser print dialog opens. The preview shows every page laid out flat, each on its own sheet, with the cover first. Headers / footers / drop caps carry through. Choose Save as PDF if you'd rather not print physical pages — close the dialog when done. The book view restores to the spread you were on.
  13. Click ▶ Audio view to exit. The reading view returns to the same scroll position around your active sentence. All work-in-progress state (bookmarks, highlights) persists; closing and reopening the clip preserves everything.

Walkthrough 5 — Install as a phone PWA

Tests: Manifest, service worker, offline shell, media-session integration on the lock screen.

  1. Open Narrative on your phone (over LAN, Cloudflare tunnel, or Fly URL — anything HTTPS or localhost). iOS: Safari → Share → Add to Home Screen. Android: Chrome → menu → Install app.
  2. Launch from the home screen. The app boots without a browser chrome (manifest's display: standalone). Theme color matches your dark/light setting.
  3. Generate or load any clip. Hit play. Lock the phone. Lock screen shows the clip title + cover art + ⏯ controls (MediaSession API). Skip-back / skip-forward should both work from the lock screen.
  4. Turn off Wi-Fi + cellular. Pull down to reload the app. The shell loads from the service worker cache — empty library is fine, but the UI itself shouldn't be a network error. Anything that needs the server (new synthesis, voice install) will fail; cached audio still plays.
  5. Turn the network back on. New synthesis works again. The SW updates itself on next page load when a newer build deploys.

Walkthrough 6 — Cross-device sync (desktop ⇄ phone)

Tests: Server-side library, per-tester isolation, push-on-save, pull-on-open, per-clip last-write-wins.

Prereq: you have Narrative installed (or just bookmarked) on two devices — typically desktop browser + phone PWA — and your tester key is pasted on both. Same key on both devices is what makes them land on the same library; if you've pasted two different keys, the devices won't see each other's clips.

  1. Desktop. Open Settings (⚙) → scroll to "Sync library across devices". The radio reads Off by default. Flip to On. The status line under the toggle changes to "Sync on. Pulling…" for a second, then settles to "Sync on. Last pulled just now."
  2. What just happened: every clip currently in your local library got pushed up to the server. From now on, every save (new clip, edited text, new bookmark, dragged re-order) auto-pushes within a few seconds. You don't have to do anything for it to happen.
  3. Phone. Open Narrative. Settings → same row, flip Sync to On. Status line transitions through "Pulling…" → "Last pulled just now."
  4. What just happened: the phone asked the server "what's in this tenant's library?" and pulled down every clip the desktop just pushed. Open the library dialog — you should see every clip from your desktop, cover art and all. (Audio streams from the server on demand the first time you play each one; after that it's cached on the phone.)
  5. Desktop edit. Open any clip. Drop a bookmark at any timestamp. Wait 5 seconds (the push is debounced — multiple edits in quick succession coalesce into one upload).
  6. Phone pull. Either wait up to 60 seconds (the phone auto-pulls on a timer) or: pull-to- refresh the page, or close the PWA from recents and reopen it. Open the same clip — the bookmark from the desktop is there.
  7. Phone edit. Add another bookmark from the phone. Wait 5 seconds. Hit refresh on the desktop. The phone's bookmark appears on the desktop side.
Per-clip last-write-wins. If you edit the same clip on both devices while one is offline, whichever side has the later "updated at" timestamp will win when they reconnect. The loser's edits are gone — not merged. In practice this is rare (you're usually editing on one device at a time), but be aware that for the same clip, sync is "newest wins," not "merge."
Sync is per-device. Flipping the toggle on the desktop does NOT auto-flip it on the phone. Each device opts in independently — useful when you want one device (say, a shared family iPad) to stay local-only.
If a clip doesn't show up after pull: check the status line on the device that made the edit. If it still says "Last pulled N min ago" with no recent timestamp, the push from that device might not have happened — verify sync is on there too. The push side is symmetric: every device with sync on both pushes its own changes and pulls everyone else's.

Sending feedback after a walkthrough

Whether something broke or just felt awkward, here's the path to get it back to the maintainer with everything needed to reproduce.

If you hit an error

  1. Open Settings (⚙ icon, top-right of the hero). Scroll near the bottom.
  2. Tap View debug log →. A modal lists every dlog entry from this session (sortable timestamps, namespaces like [bg-queue], [synth], [github]). Tap Download (.txt) in the dialog header. A file named narrative-debug-YYYY-MM-DDTHH-MM.txt lands in your Downloads folder.
  3. Back in Settings, tap one of the two feedback buttons:
    • Send feedback (mail app) → opens your phone's default mail app with the subject prefilled ("Narrative feedback — vNNN") and a body that already includes your build version, the currently-loaded clip's id, and a blank space to describe what happened.
    • Send feedback (Gmail) → opens the same draft inside Gmail's web compose at mail.google.com. Useful when you don't have a system mail app configured (or you're on a shared machine and don't want to lose the draft to a browser refresh — Gmail's web compose autosaves).
  4. Attach the debug log file you just downloaded. Both mail-app and Gmail flows let you drop attachments. The maintainer needs that file to see what your client + server saw at each step.
  5. Describe the problem in plain language. "Tried to import these 4 chapters; chapter 1 took 30s and the rest failed instantly" beats "didn't work" by a mile. Mention which walkthrough you were on if applicable.

If something just felt off (no error)

You don't have to attach a log for UX feedback. Just hit either Send feedback button and describe what you expected vs what happened. A screenshot helps a lot — most phone mail apps let you paste one inline.

The auto-context the feedback buttons inject (build version, currently-loaded clip id) makes a real difference. If you compose the email by hand without clicking those buttons, the maintainer ends up asking "what version are you on?" first. Saves a round-trip.
Don't include a debug log in a public bug report if you've narrated anything sensitive. The debug log captures clip titles, character names, sample text from the chapter queue, and GitHub repo paths. If you narrated a personal letter or a private manuscript, those details land in the log. The maintainer is fine — they're the only recipient of the feedback emails — but a screenshot posted publicly should be reviewed first.
