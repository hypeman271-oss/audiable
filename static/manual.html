2. Getting text in

The text card has five link-style actions in its header:

Action What it does
Clear Empties the textarea + decouples from any loaded clip. Use it when you're done with one piece and want to start a new one without refreshing.
Paste URL Opens an inline URL input. Paste any article URL (blog post, Wikipedia, news), hit Enter, and the server fetches it, extracts the main article via trafilatura (drops nav, ads, comments), and drops the clean text in the textarea. SSRF-guarded: only public HTTP(S) URLs allowed.
Upload file .txt · .md · .pdf · .epub · .docx. PDFs go through a cleanup pipeline: page numbers stripped, repeated headers/footers detected and removed across pages, mid- sentence page breaks bridged so the splitter doesn't cut "the cat sat on the | mat" into two sentences. 25 MB cap.
Save text (Only visible when a clip is loaded.) Writes any edits in the textarea back into the currently-loaded clip in the library. If the number of sentences changed, an auto-regen kicks off so the audio matches the new text. Typo fixes that don't change sentence count save instantly with no resynthesis.
Edit text (Only visible while you're in the reading view.) Hides the reading view, shows the textarea with the clip's full text ready to edit. Save text writes it back; Generate creates a new clip instead.

3. Choosing a voice

Voice picker

The dropdown lists every installed voice, grouped by engine:

  • Neural (high quality) — Piper voices, ~30–130 MB each. Sound natural.
  • System voices — your OS's built-in TTS (SAPI on Windows). Always available, lower quality.

Multi-speaker voices like LibriTTS ship 904 distinct speakers in one model — when one of those is selected, a Speaker picker appears below with options Speaker 0 through Speaker N-1. A small ▶ button next to the speaker dropdown plays a preview of the selected speaker.

Browse voices

Tap Browse voices to open the catalog: ~160 voices across ~30 languages. Each row has:

  • ▶ Preview — proxies the official sample MP3 from HuggingFace, plays inline.
  • Install — streams the .onnx + .onnx.json over SSE with a live percentage in the button label (0% → 100% → Installed). Lands directly in your voices/ folder.
  • × Remove — appears for installed voices only; deletes both files and frees disk.

Above the catalog, an Installed only (N) chip filters to only the voices you have. The search input filters by language, country, or name.

Speed & volume

Two sliders affect synthesis only — they get baked into the generated audio. For changing playback speed on an existing clip, use the 1× chip on the player instead (see Section 4).

Saved presets

Found a voice + speed + volume combo you like? Hit Save preset, name it (e.g. "Audiobook narrator"), and a chip appears under the voice picker. Tap the chip to re-apply all four settings. Long-press / × deletes.

Characters (Author mode)

Assign different voices to different characters in your draft. See Author mode below.

4. The player

Above the native browser audio control, there's a row of action chips. Left to right:

↶ 5s — Skip-back

Tap to rewind 5 seconds. "I zoned out for a moment" recovery. Different from the lock-screen prev/next which jump a whole sentence.

🔖 Bookmark

Drops a bookmark at the current audio position. The chip's label updates to show the count (🔖 Bookmark · 3), and a list appears under the player:

  • Tap the time on the left to jump there and play.
  • Tap the note field, type a reminder, press Enter or click away to save.
  • Bookmarks live with the clip in the library (export/import too).
  • Auto-regen on save-text preserves bookmarks even if the audio is rebuilt.

A↔B loop

Re-listen to a tricky passage. Cycles through four states on tap:

  1. A↔B — idle.
  2. A 1:23 — A captured at current time, waiting for B.
  3. ↻ 1:23–2:45 (accent background) — both set, looping. Playback resets to A whenever it crosses B.
  4. Tap once more to clear.
Loading a different clip clears the loop bounds (they belonged to a different audio track).

💤 Sleep timer

Cycles Off → 15 → 30 → 45 → 60 min. When the timer expires, audio fades over 5 seconds and pauses gracefully — your saved resume position lands at the exact moment of fade-out, so the next morning the clip starts where you fell asleep.

Playback speed (1×)

Cycles 1× → 1.25× → 1.5× → 1.75× → 2× → 0.75× → 1×. Affects playback only, not stored audio. Choice is persisted per browser. Reapplied automatically when the audio source changes (per-sentence streaming, clip switch).

5. Reading view

Once a clip is playing, the textarea swaps for the reading view: the source text rendered as clickable sentence spans. The active sentence is highlighted; played sentences fade slightly so you can see your progress.

  • Tap a sentence to seek there and keep playing.
  • The active sentence stays in view inside the reading-view box (the box has its own internal scroll, so it never yanks the rest of the page around).
  • Tap Edit text in the text-card header to go back to the textarea for edits.
On phone, the lock-screen prev/next buttons jump by whole sentences — useful when you missed context, not just a word. The on-screen ↶ 5s is for the missed-a-word case.

6. The library

Every clip you generate is auto-saved into a per-browser library (IndexedDB). Newest clips appear at the top by default.

Card anatomy

ElementWhat it does
⋮⋮Drag handle. Press, drag up or down, release to reorder. Works for mouse and touch.
Card bodyTap anywhere on the title/meta area to load and play this clip.
↺ ResetOnly shown for in-progress clips. Wipes the saved resume position so next play starts from the top. If you reset the clip you're currently listening to, the player rewinds too.
✎ EditOpens a dialog to rename and add a note (e.g. "Chapter 3 — needs work on the kitchen scene").
×Delete. No confirm — gone immediately.

Sections

The list splits into two sections automatically:

  • CONTINUE LISTENING — clips with a saved resume position (you started but didn't finish). Always at the top so "where was I" is one tap.
  • OTHER CLIPS — everything else. Same sort + filter as the top section.

Both sections respect the active sort mode. If a clip plays to the end, it auto-moves down to Other Clips on next render.

Search + sort + filter

  • Search box matches title, source text, voice name, OR note text. Press Esc to clear.
  • Sort chip cycles Newest → Oldest → Longest → Shortest → Custom → Shuffle. Custom uses your drag-defined order; auto-switches on the first drag.
  • Hide played (in the library tools row) hides clips you've finished and reset. Becomes "Show all" when active. State persisted.

Drag to reorder

Tap and drag the ⋮⋮ handle on any card. Releasing flips the sort mode to Custom order and persists. Auto-advance plays through clips in the order you see them — so dragging chapters into reading order means the audiobook just works.

Reordering inside Continue Listening reorders within that section. When a clip's resume position is cleared (manual ↺ reset or auto-advance to next), it drops down into Other Clips at the position you put it.

Auto-advance

When a clip ends, the next one in your chosen sort order starts automatically — with a 3-second breath between them. Status shows "Up next in 3s…".

If you tap a different clip or hit Clear during the gap, the queued load is cancelled.

Export / Import

Below the search:

  • Export — builds a zip containing every clip as MP3 plus a JSON manifest.json with all metadata (titles, notes, voices, speakers, sentence offsets, resume positions, bookmarks, presets, library order, play mode). Downloads as narrative-library-YYYY-MM-DD.zip.
  • Import — pick a previously-exported zip. Clips with IDs that already exist are skipped (so re-imports are safe). Restores presets and custom order too.
The zip is a real PKZIP file — your phone's Files app can open it, you can extract individual MP3s with any zip tool, the manifest is human-readable JSON.

7. Settings & Author mode

The ⚙ at the top right opens Settings. One toggle for now: Author mode. Off by default.

Flipping it on reveals:

  • Word count + read-aloud time in the textarea meta line: 1,247 / 500,000 · 247 words · ~1:22 at 180 wpm. Updates live as you type or move the speed slider.
  • Characters link in the voice card label-row — opens the character roster dialog.
  • More writing-craft features will slot in here (long- sentence highlighter, filler-word callouts, chapter auto- split, etc).

Character voices

Open Characters and add one row per character. For each: name, voice, and (if the chosen voice is multi- speaker like LibriTTS) a speaker ID.

When you hit Generate, Narrative scans your text sentence by sentence. A sentence containing a quote ("…", "…", etc.) AND a character's name as a whole word is routed through that character's voice. Other sentences use the main voice picker (your narrator).

Detected patterns:

  • "Welcome," said Sarah. → Sarah's voice
  • Sarah said, "I'll be quick." → Sarah's voice
  • "Hello." Sarah walked into the room. → Sarah (name appears with quote)
  • Pronoun-only attribution ("How are you?" she asked.) doesn't resolve — falls through to the narrator.
If you assign two characters voices from different Piper models with different sample rates (e.g. one _low 16 kHz and one _high 22 kHz), the multi-voice synthesis will fail with a clear error in the status line. Pick voices from the same quality tier (all medium or all high) to mix cleanly.

8. Listening on your phone

Quick tunnel (no setup)

In a terminal on the machine running Narrative: 

python scripts/tunnel.py

After a few seconds you get a public https://<random>.trycloudflare.com URL. Open it on your phone — works over cellular, not just home Wi-Fi. The service worker registers properly, the PWA install prompt fires on Android, and on iOS it's Safari → Share → Add to Home Screen.

First time you'll need cloudflared installed: 

winget install --id Cloudflare.cloudflared    # Windows
brew install cloudflared                       # macOS

Each restart of tunnel.py gives a new random URL. To get a stable URL, see Named tunnel below.

Named tunnel (persistent URL)

One-time setup if you own a domain on Cloudflare: 

cloudflared tunnel login
cloudflared tunnel create narrative
cloudflared tunnel route dns narrative narrative.yourdomain.com

Then run:

python scripts/tunnel.py --name narrative

The URL https://narrative.yourdomain.com stays the same across restarts, so the PWA on your phone stays installed at one address forever.

Lock down with X-Narrative-Key

When the tunnel is up your TTS endpoint is reachable from anywhere. Stop random visitors from using your CPU: 

$env:NARRATIVE_KEY = 'paste-the-suggested-key-from-server-banner'
python server.py

With NARRATIVE_KEY set, all /api/* requests require X-Narrative-Key as a header. The first time you open the URL on your phone, the app prompts you for the key. It's saved in your phone's localStorage and sent automatically forever.

Workflow ideas

  • Audiobook a book chapter-by-chapter. Paste chapter 1 → Generate → save. Repeat for each chapter. Drag-reorder by chapter number. Hit play on chapter 1 — auto-advance plays the whole book in order with 3-second breaths between chapters.
  • Read articles you'll never read. Phone PWA + tunnel + Paste URL. The Continue Listening shelf handles "I started this on my commute, finish on the train home."
  • Revise your own writing. Author mode on. Generate. Walk around. Tap 🔖 every time you hear something to fix; type quick notes when you stop. Back at your desk, tap each bookmark's time to re-hear it, fix the manuscript, Save text — auto-regen if sentence count changed — listen again. Repeat.
  • Stress-test dialogue. Author mode → add your characters with distinct LibriTTS speakers → Generate a chapter. If two characters' dialogue sounds the same in your own ears, your prose may be confusing them on the page too.

Where your data lives

  • Library (clips + bookmarks + notes) — IndexedDB audiable database in your browser. Per-browser-profile, per-origin.
  • Voice models — voices/*.onnx on the server machine.
  • Synthesis presets + library order + custom config — localStorage keys under narrative.*.
  • Uploaded files (PDFs, etc.) — extracted in memory on the server, never saved to disk.
Use Export regularly to back up everything as a single zip. The whole library state restores cleanly on any device.
