What's new

Notable changes shipped since the start of the alpha. Newest at the top. Build versions track the service-worker cache so you can tell what you're running by checking Settings → Send feedback (the build line in the auto-context).

v89 Piper "# channels not specified" fix
  • Synthesis no longer dies on certain edge-case sentences. Some inputs (notably those starting with non-speech punctuation like "|| July 2024" or "[1]") caused Piper's WAV writer to skip the channel-count header, which then made the whole synthesis blow up with a cryptic "# channels not specified" error. The wave file now gets pre-initialized with valid mono defaults so even no-audio outputs produce a well-formed WAV, and any sentence that still fails falls back to silence so the rest of the chapter still synthesizes. Verified end-to-end on the Paul Graham "Persistence and Obstinacy" essay that triggered the bug — 14 sentences, 2.7 MB combined WAV, 502 KB MP3, zero errors.
v88 Clearer errors during server cold start
  • Generate now fails fast when no voice is selected. Clicking Generate with an empty voice dropdown used to route through to the SAPI fallback, produce a malformed WAV, and surface the worst error message in the app — "mp3 encode failed". Now it says "Pick a voice first — the dropdown is empty" before any of that runs.
  • Voice catalog auto-retries on 503. The usual cause for an empty voice dropdown is the server still waking up (Fly.io cold-start, slow first import). The app now shows "Server is waking up — retrying in 10s…" and keeps trying until the catalog loads. No more silent empty dropdown + baffling encode error.
v87 Chapter queue stays in sync with playback
  • Chapter auto-advance now waits for the audio to actually finish. Previously, chapter N+1 started synthesizing the moment chapter N's synthesis completed — but the user might still be listening to chapter N. When chapter N+1's first sentence arrived, it rebuilt the reading view and stole the player, leaving the audio and text out of sync. Now the next chapter's synthesis and text-swap are deferred until the playerEl 'ended' event fires, so transitions happen at the natural pause between chapters.
  • Cancel-queue cleanup. Hitting the × on the chapter queue pill now fully clears the queue state, so a cancelled queue doesn't flash a misleading "All N chapters synthesized" message later.
v86 Ghost UI elements purged
  • Stale placeholders no longer appear on page load. Nine UI elements (the chapter banner, the queue pill, the URL input row, the mini player, and several others) had CSS display: flex rules that quietly overrode the browser's default behavior for the hidden attribute. So they were visible on every fresh page load, showing whatever placeholder text was hardcoded into the HTML — including a phantom "Chapter 1 of 1" queue pill and a "0 chapters detected" banner that weren't real. Fixed by restoring the spec-defined hidden semantics with one CSS rule. Same class of bug as the v79 Settings dialog regression; regression test added.
v85 Project Gutenberg chapter detection
  • Tom Sawyer (and every other PG book) now splits into chapters. Project Gutenberg wraps chapter titles in HTML that trafilatura was identifying as boilerplate and stripping out — the entire novel arrived as one continuous river of prose with nothing for the chapter detector to grab. The server now BeautifulSoup-parses the raw HTML, pulls h1-h3 tags back out, and re-injects them as markdown ## CHAPTER I markers in front of the matching prose. Works on Project Gutenberg, Standard Ebooks, and anything else with proper heading tags.
  • Chapter title cleanup. Headings that arrive in ALL CAPS ("CHAPTER I") get title-cased to "Chapter I" in the library so the row labels read consistently with the Standard Ebooks bare-numeral path.
v84 Chapter detection for novel-length URL fetches
  • Chapter auto-split now finds chapters in a whole novel. The cap on suggested chapters was 30, which silently swallowed Tom Sawyer (35 chapters) and most other full-length books extracted from URLs — the banner just never appeared. Raised to 200, which covers virtually every novel.
  • Roman-numeral chapter headings get readable titles. Standard Ebooks renders chapter headings as bare Roman numerals ("## I", "## II") instead of the usual "## Chapter 1". The detector now promotes those to "Chapter I" / "Chapter II" so the library cards make sense at a glance.
v83 Illustrations from URL fetches
  • Inline images in the reading view. When you paste a URL with embedded illustrations (Project Gutenberg, Standard Ebooks, a Substack post with a hero image), the pictures now appear between sentences in the reading view as the audio plays. They're stripped from the spoken text so nothing reads "image colon a cat sitting on a fence." Images live with the clip — they survive a save, a reload, and a re-narrate. (Stored as URLs for now; if the source goes down or you go offline, they break gracefully.)
v65 Author — smarter dialogue routing
  • Gender-aware character detection. The Characters dialog now has a He / She / They column. When you've set it, lines with pronoun-only attribution ("How are you?" she asked.) route to the right character even when the named speaker is several sentences back. ~85% accuracy on mixed-gender scenes, up from ~75%.
v62 – v64 Bug fixes + dialogue v1
  • Send feedback works again. The button was silently broken by a URI encoding bug — every alpha tester who tried it just saw nothing happen. Now it opens your default mail app, copies the address to your clipboard as a fallback, and shows a confirmation in the status line.
  • Send feedback (Gmail) → separate link for when your OS default mail app is something you don't actually check.
  • Tier 1 character detection. Paragraph-aware speaker cursor. "He said hello" now correctly attributes when the named speaker ("John walked in.") was in the previous sentence — and the cursor resets at every paragraph break so a new speaker doesn't inherit the old one.
v56 – v61 Voice browser — audition voices on your own text
  • Custom preview text. Paste a sentence from your manuscript above the catalog. Tap ▶ on any voice to hear that sentence in that voice — installed or not.
  • Auditions are temporary. Tapping ▶ on an uninstalled voice installs it just long enough to preview your text. The Install pill turns into a "Keep" button — tap it to commit, or close the dialog and the install auto-reverts. Try voices freely without filling up disk.
  • Language filter. Drop-down above the catalog narrows ~160 voices to just the ones in your language. Each Piper voice only speaks the language it was trained on; this hides the rest.
v53 – v55 Manual rewrite
  • The illustrations in the manual are now real app components, not hand-drawn approximations. They inherit the live theme, update automatically when the app evolves, and won't drift out of date.
  • The page-layout diagram at the top is now a live mini-app with side-callouts explaining what each card is for.
v50 – v52 Author — writing-health signals
  • Filler-word callout — live chip strip below the textarea shows counts of just / very / really / that / kind of etc. Top 8 by frequency. Author mode only.
  • Long-sentence highlighter — sentences over 35 words get a warm amber wash in the reading view, so you can see run-on candidates while you listen back. Author mode only.
  • Voice favorites (★). Star voices you like; they float to the top of the main picker in a "★ Favorites" group, and a "★ Favorites only" filter chip narrows the catalog.
v46 – v49 Reader polish
  • Light theme. Settings → Theme: Auto / Dark / Light. Auto follows your system. Light uses a warm cream palette tuned for daytime / outdoor reading.
  • Chapter auto-split on paste. Paste a book with Chapter N headings (or markdown # Chapter headings) and a banner offers to split it into separate clips. Tap Split, click Generate once, the rest auto-continue in sequence — each chapter saved with its heading as the title.
  • 5-second skip-forward chip — the matching half of the existing ↶5s back. The full pair: ↶5s · 5s↷.
  • Listen stats in Settings. Today / this week / all-time playback time, top voice, most-listened clip. Reset on demand.
v45 Mobile parity
  • Long-press tooltips. Every button with a title attribute (which on desktop appears as a hover hint) now surfaces the same hint on a ~500 ms hold on touch devices. Mobile users finally get the same affordance as desktop.
