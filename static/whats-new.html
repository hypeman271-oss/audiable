What's new

Notable changes shipped since the start of the alpha. Newest at the top. Build versions track the service-worker cache so you can tell what you're running by checking Settings → Send feedback (the build line in the auto-context).

v180 Sign in with GitHub (OAuth)
  • One-click GitHub sign-in, no more PAT paste. Settings → GitHub now has a Sign in with GitHub button. Click it, authorize on github.com, you're back on Narrative with the token already saved. Settings shows Signed in as @yourhandle. PAT paste stays as the fallback (fine-grained tokens, GitHub Enterprise, unconfigured servers).
  • Operator step (one-time): register a GitHub OAuth App, drop the client ID + secret into env vars. See OAUTH_SETUP.md for the walkthrough. Until configured, the Sign-in button stays disabled with an actionable tooltip — paste keeps working.
  • Token never hits the access log. The callback delivers the token via URL fragment (which browsers don't send to the server). Frontend boot reads it, stores it, and clears the URL so a reload doesn't re-process or leak anything.
v179 GitHub: branch picker, gitRef on Edit, folder chips
  • Branch dropdown in the picker. Repos with feature branches now surface a Branch: dropdown above the file list. Switching swaps the tree instantly — no need to edit the URL into /tree/<branch>/ form by hand. Powered by a new /api/github/branches endpoint that lists the repo's branches with the default sorted first.
  • Commit SHA on the Edit dialog. GitHub-sourced clips now show a "From GitHub: chapter_02.md @ a1b2c3d" line in the Edit dialog — confirm at a glance that the clip matches the commit you just pushed. Hover the SHA pill for the full hash.
  • "Filter to chapters/" auto-suggest. When the picker spots a common manuscript folder (chapters/, manuscript/, src/, content/, etc.) with three or more files, it offers one-click filter chips — cuts the visual noise on big repos.
v178 Confetti is testable again
  • Replay onboarding tips → actually fires the confetti. v175 hid confetti behind a 0→≥1 transition gate that anyone with clips already on file could never satisfy. Replay now also resets the internal counter so the next library render correctly registers as "first clip" and the burst pops. Confetti's gate decisions also write to the debug log so a "didn't fire" report is one click of "View debug log" away from a diagnosis.
v177 Debug log + empty-text guard
  • "chapter X keeps failing" is now diagnosable. Every GitHub fetch, queue enqueue, synthesis start, HTTP error, SSE error, and retry writes a timestamped entry to an in-app debug log. Open it from ⚙ Settings → View debug log → or straight from the failures banner's new View log button. Copy, download as .txt, or clear.
  • Empty-text chapters never reach the queue. Some files (TOC, image-only chapters, all-frontmatter) return empty text after trafilatura strips boilerplate. Those chapters used to enter the queue and fail with a confusing "no audio in result" — now they're skipped at the fetch stage with a debug-log entry explaining why, and the status bar tells you how many were skipped.
v176 GitHub flow: recents, imported badges, re-narrate outdated
  • Up to 5 recent repos. The "+ Add more from owner/repo" footer is now a row of chips covering your last 5 GitHub projects — flip between books without re-pasting URLs. The Import → GitHub field shows the same chips above the input ("Switch to:") when you have more than one recent.
  • ✓ "Already imported" badges in the picker. Re-open a repo and the picker now flags files that are either in your library or sitting in the queue with a dim row + a ✓ chip. A new Hide already imported toggle lets you collapse the list to just the chapters you still need to add.
  • Re-narrate outdated → background queue. The missing companion to Sync GitHub. After Sync flags clips with newer upstream commits, the new Re-narrate outdated (N) button refetches each one and queues it for re-synthesis. Title, notes, bookmarks, cover, and tags all survive — only the text and audio are replaced.
v175 🎉 Confetti for your first clip
  • The first time you save a clip, paper confetti rains from the top of the page. Fires exactly once — only on the genuine 0 → 1 transition, not when you reload with clips already on file. Respects prefers-reduced-motion if you've turned animations down at the OS level. Want to see it again? ⚙ Settings → Replay onboarding tips →.
v174 "Replay onboarding tips" in Settings
  • Bring the tips back. If you dismissed a first-tap hint, the audition banner, or the first-clip tour and want to see them again, Settings now has a Replay onboarding tips → link that clears every once-per-device flag and re-renders the surfaces so the tips pop back without a reload.
v173 First-clip tour moves into the hero
  • Tour sits in the empty space between Narrative and the icon rail. Even at the top of the page it kept getting glanced past; putting it inside the hero row — directly in the left-to-right scan — makes it impossible to miss. On phone widths it wraps to its own line below the title.
v172 First-clip tour at the top of the page
  • Tour banner lifted to the top. Right below the hero, above every card — so it's the first thing you see after Generate finishes, without scrolling past the text card to reach it.
v171 First-clip tour now actually surfaces after Generate
  • "This is your first clip" banner above the player. The v168 onboarding tour lived inside the library dialog, so first-time users only saw it if they manually opened the library after Generate. Moved above the player card so it shows up the moment your first clip lands. Points at the three discoverability surfaces you can act on right now: ✎ Edit (covers), ⋮⋮ drag-to-reorder, and 📝 Notes. Dismiss with × — once-per-device.
v170 Audition tip surfaces (for real this time)
  • "904 speakers? Tap Audition" banner now actually shows. The v168 first-tap hint fired a status message that was hidden behind the voice dialog itself, so first-time LibriTTS users never saw it. Replaced with a persistent inline banner that lives next to the Audition link — dismissible with × or auto-hides the moment you open the wizard.
v169 Live elapsed time on the synthesis queue
  • "Elapsed 0:45 · ~0:12 left" on the in-flight job. The background queue panel now shows a live timer for the chapter currently being synthesized. Once a few sentences have completed, an ETA appears next to it so you can tell at a glance whether to wait or step away.
v152 Polish pass — tooltips, shortcuts overlay, clearer copy
  • Press ? for a shortcuts overlay. A new dialog lists every keyboard shortcut Narrative knows about — Ctrl+Enter to generate, Esc to clear search, Enter to fetch URLs, and more. Reach it via ? (when you're not typing in a field) or Settings → Keyboard shortcuts.
  • "What's a speaker?" link. The Speaker row in the voice dialog now has a tiny ? button that explains what numbered speakers actually are on LibriTTS-style multi-speaker voices.
  • Re-narrate banner reads clearer. When you change voices mid-clip, the prompt now spells out what carries over (bookmarks, notes, saved position) and the dismiss button reads "Not now" instead of just Dismiss.
  • Tooltips on Generate / Download. Hovering each primary button now reveals a plain-English explanation of what it does — useful for hover-savvy users who land in a fresh tab.
v150 Discoverability pass — cycle chips, covers, and mode unlocks
  • First-tap hints on Sleep / A↔B / Speed. The cycle chips now whisper one-shot hints the first time you tap them ("Tap Sleep again to cycle: 15 / 30 / 45 / 60 min · end of chapter · off"). Hint fires once-ever per chip; subsequent taps are silent.
  • "+ Cover" affordance on cards without art. Library cards whose swatch is still the title-hash gradient pick up a quiet "+ Cover" chip next to ✎ Edit. Tapping it opens Edit dialog scrolled straight to the cover picker — no hunting through fields. Disappears once the clip has a cover uploaded.
  • Mode picker shows what you'd unlock. Settings → Mode now appends an accent-tinted "+ unlocks" note that updates with your pick: Simple sees what both Standard and Author add; Standard sees what Author adds; Author sees nothing (already there).
v149 First-run discoverability pass — fewer "where do I start?" moments
  • Import dropdown items now have descriptions. Upload file says "PDF, EPUB, DOCX, TXT, MD"; GitHub repo says "Browse a repo and pick chapters"; Scrivener and Obsidian explain what they are. No more guessing what each item does before clicking.
  • First-run starter card. Brand-new testers — empty library, empty textarea — get a "Get started" panel with three clickable cards: paste an article URL, upload a file, or browse a GitHub repo. Auto-hides the moment you type or save your first clip.
  • Drag-to-reorder discovery hint. The ⋮⋮ drag handles on library cards now come with a one-time tip banner above the list (when you have 2+ clips). Auto-dismisses on your first successful drag, or via the ×.
  • GitHub help opens by default for first-time users. The "Show me what to copy from GitHub" disclosure in Settings → GitHub is open out of the box when no token is saved (visual guide right there when you need it). Once you've saved a token — or toggled the disclosure manually — it remembers your choice.
v139 Background imports — queue chapters silently while you're away
  • Background mode in the import picker. When you pick multiple chapters from GitHub, Scrivener, or an Obsidian vault, a new Background — don't auto-play checkbox appears next to Use. Tick it and the chapters synthesize one after another in the background; nothing ever loads into the player. Perfect for kicking off an overnight import and coming back to a populated library.
  • Cancel anytime. The chapter pill shows Background · chapter 3 of 12 · Next: … while the queue runs. Hit Cancel on the pill and the in-flight chapter aborts immediately; chapters already saved stay in your library.
  • Voice settings are captured at synthesis time. If you change the voice mid-queue, the chapter currently synthesizing keeps the voice it started with; subsequent chapters use the new pick.
v138 Per-clip notes — a scratchpad for each chapter
  • Free-form notes attached to every clip. A multi-line scratchpad separate from the one-line Note label — for edits to revisit, voice direction, continuity reminders, beat-sheet thoughts. Edit dialog now has a Notes field below the existing Note.
  • 📝 chip in the player. While a clip is loaded, the new chip in the player row opens a focused notes editor — just the clip title and a big textarea, so you can jot something mid-listen without leaving the page. Closes saves automatically; cards pick up a small 📝 Notes indicator once notes are present.
  • Round-trips through Export / Import. Notes travel inside the library zip's manifest alongside bookmarks and tags, so a fresh device picks up everything you've written.
v125 Story-board covers per chapter
  • Upload custom cover art per clip. Edit → Cover image lets you drop a story-board image (PNG / JPG / WebP / GIF) onto each chapter. It's auto-resized to a 256×256 square and JPEG-compressed (~20-30 KB per cover) so 100 chapters add about 2 MB to your library.
  • Libby-style color tint. Each upload's dominant color is sampled and used as a soft 12% wash across the matching library card. Clips without an uploaded cover still get a tint — derived from the title hash — so every card has a unique color identity at a glance.
  • Cover images travel with Export / Import. Library zip now includes a covers/ folder alongside audio/. Older zips without covers still import cleanly; existing clips without covers fall back to the gradient swatch.
v111 Icon-rail UX — text window dominates
  • Voice and Library moved into dialogs opened from icons in the hero: 🎤 [Voice Name] ▾ and 📚 Library (with a clip-count badge). The text window now dominates every viewport — no sidebar, no two- column desktop grid. Same UX from phone to desktop.
  • Voice trigger shows the active voice so you always see what'll narrate without opening the dialog.
  • Library badge shows clip count in the hero, hidden when the library is empty.
  • Desktop max-width loosened to 960px / 1080px wide. Without a 360px sidebar competing for space, the textarea now stretches close to its typographic comfort zone (~85-90 chars) on regular desktops and ~100 chars on wide screens.
v109 Libby/Hoopla-inspired listener polish
  • Chapter-end sleep timer. The sleep chip's cycle now ends with "Chapter end" (with a queue) or "Clip end" (without) — stop at the next natural narrative boundary instead of guessing how many minutes are left.
  • Customizable skip interval. Settings → Skip interval picks 2 / 5 / 10 / 15 / 30 seconds. The ↶ and ↷ chips update their labels to match.
  • Global bookmark timeline. Library tools → "All bookmarks" opens a single view of every bookmark across every clip — grouped by clip, sortable by recency / time- in-clip / title. Each row jumps straight to that bookmark. Made for authors revising a long manuscript.
  • Clip tags. Edit a clip to add free-form comma-separated tags ("draft", "needs revision", "fiction"). Tags render as colored chips on the card; a filter chip row above the library composes AND-style across selected tags.
  • Cover-art swatches. Each library card grows a hash-derived gradient tile with the title initial. Same title → same swatch on every device, making a 50-clip library scannable at a glance.
  • Speed-aware duration. At any speed other than 1×, the player shows "· 1h 50m left" beside the duration, computed from current position. The speed chip's tooltip carries the full breakdown.
v107 Import dropdown · Scrivener · Obsidian
  • One Import menu replaces the old Upload + Paste URL buttons. Five sources: Upload file, Paste URL, GitHub repo, Scrivener bundle, Obsidian vault. The text card stays uncluttered as more sources land.
  • Scrivener bundle import. Drop in a .scriv.zip; the parser walks the binder XML in author-defined order, reads each scene's RTF, and skips Research / Trash. Pick chapters in a filterable picker; single-select loads to the textarea, multi-select builds a chapter queue.
  • Obsidian vault import. Drop in a .zip of your vault; the parser walks every .md, skipping .obsidian/, .trash/, templates/, attachments/. YAML title: frontmatter overrides the filename; [[wikilinks]] are flattened to plain text and ![[embeds]] are dropped so nothing nonsense gets read aloud.
  • GitHub repo browser + auto-sync (shipped over v100–v104). Paste a github.com/owner/repo URL or pick GitHub repo from Import; the browser lists every .md / .txt / .docx / .pdf / .epub in the tree. Private repos work with a PAT in Settings. Each clip remembers its file SHA; the library's Sync all from GitHub button flags any clip whose source has been updated upstream and offers a one-click re-narrate.
  • Under the hood: GitHub, Scrivener, and Obsidian browsers now share one document-picker component, so future sources (Word, Google Docs, Ulysses) plug in as new menu items instead of new dialogs.
v97 Illustrated books from Project Gutenberg
  • Inline images now extract from Project Gutenberg illustrated editions. Same root cause as v85's heading injection — trafilatura was stripping <img> tags from PG body content the same way it stripped <h2> tags. The server now BeautifulSoup-parses the raw HTML, finds img tags, and re-injects them as markdown ![alt](src) markers anchored to the matching paragraph. Verified end-to-end on Huckleberry Finn: 113 illustrations across 43 chapters, all anchored to their proper sentence positions.
  • Decorative ornament filter. Small (under 100px) divider / spacer / ornament images get skipped so the reading view isn't littered with section breaks between paragraphs.
v96 Adaptive layout for desktop and tablet
  • Two-column layout on desktop screens (1024px+). The reader workflow (text card → Generate → player → chips) stays in a 640px-wide left column where line width is comfortable for reading; voice picker and library sit in the right column. Side-by-side with Scrivener or Word, you can keep both visible without scrolling.
  • Library cards in a grid. 1 column on mobile (unchanged), 2 columns at 768px+, 3 columns at 1280px+. Tom Sawyer's 35 chapters now visible at a glance instead of requiring a long scroll.
  • Tablet (600-1023px) gets slightly more breathing room in its single column, sized for iPad-portrait ergonomics.
v94 Custom audio player
  • Replaced the browser's native audio control bar with our own. Single rounded-pill row: play/pause, current time, scrubber with buffered fill, duration, mute. Consistent look in Chrome, Safari, Firefox (no more "looks like Chrome's media controls"). The underlying <audio> element is still doing all the work; we just stopped showing its UI. Skip 5s, bookmark, sleep, A↔B loop, and speed cycle chips unchanged below.
  • Scrubber keyboard support. Focus the scrubber and use ← / → to seek 5s, Home / End to jump to the start/end.
v93 Chapters pre-synthesize in the background
  • Chapter N+1 now synthesizes while you listen to chapter N. The moment chapter N's save completes, a background SSE fetch starts on chapter N+1 and saves the result to your library. When chapter N's audio ends, the next chapter loads instantly from the library instead of making you wait 5-15 seconds for synthesis to start fresh. Side benefit: pre-synthesized chapters show up in your library normally, so you can browse them or jump around.
  • Polite breath between chapters trimmed from 4s to 2s. Combined with pre-synth, the total gap between chapters is now ~2 seconds instead of ~5-15. Long enough to register "one chapter ended, another's starting"; short enough that an attentive listener barely notices.
v92 Skip front-matter junk in chapter split
  • Table of Contents and similar sections no longer become clips in the chapter queue. Project Gutenberg books surface CONTENTS, ILLUSTRATIONS, and other front matter as their own headings, and the v85 heading injection was correctly picking them up — but synthesizing "CHAPTER I. (pause) CHAPTER II. (pause)..." 35 times in a row isn't a thing anyone wants to listen to. The detector now drops chapters whose title matches a blocklist (Contents, Illustrations, Index, Glossary, Imprint, Copyright, Acknowledgements, About…), plus a heuristic fallback for TOC content under a non-standard title. Preface, Foreword, and Introduction are intentionally kept — those are usually real prose worth hearing.
v91 Chapter queue advance: two-flag rendezvous
  • v90's chapter advance could deadlock when the synthesis save completed after the audio finished playing (or vice versa) — whichever fired second found the other side's flag already cleared and silently gave up, leaving chapter 2 unstarted forever. Replaced the single flag with two (_queueAudioComplete, _queueSaveComplete) plus a _tryAdvanceQueue helper that fires the 4-second polite breath only when both are true. Either ordering works, neither side can race the other into oblivion.
v90 Chapter queue (really) waits for chapter end
  • v87's chapter-queue fix had a race condition. The check "if the player has already ended, advance now" turned out to fire at exactly the wrong moment — the moment the last per-sentence WAV finished playing, which is the same moment synthesis completes for long chapters. Net effect: chapter 2 still started mid-chapter-1, exactly the bug v87 was meant to fix. v90 removes the immediate- advance branch entirely and relies on two events to trigger the next chapter, with a 4-second polite breath between them: either the combined MP3's ended (user listened through the full file) or the streaming queue's ended (user finished hearing every per-sentence WAV live). Whichever fires first wins.
v89 Piper "# channels not specified" fix
  • Synthesis no longer dies on certain edge-case sentences. Some inputs (notably those starting with non-speech punctuation like "|| July 2024" or "[1]") caused Piper's WAV writer to skip the channel-count header, which then made the whole synthesis blow up with a cryptic "# channels not specified" error. The wave file now gets pre-initialized with valid mono defaults so even no-audio outputs produce a well-formed WAV, and any sentence that still fails falls back to silence so the rest of the chapter still synthesizes. Verified end-to-end on the Paul Graham "Persistence and Obstinacy" essay that triggered the bug — 14 sentences, 2.7 MB combined WAV, 502 KB MP3, zero errors.
v88 Clearer errors during server cold start
  • Generate now fails fast when no voice is selected. Clicking Generate with an empty voice dropdown used to route through to the SAPI fallback, produce a malformed WAV, and surface the worst error message in the app — "mp3 encode failed". Now it says "Pick a voice first — the dropdown is empty" before any of that runs.
  • Voice catalog auto-retries on 503. The usual cause for an empty voice dropdown is the server still waking up (Fly.io cold-start, slow first import). The app now shows "Server is waking up — retrying in 10s…" and keeps trying until the catalog loads. No more silent empty dropdown + baffling encode error.
v87 Chapter queue stays in sync with playback
  • Chapter auto-advance now waits for the audio to actually finish. Previously, chapter N+1 started synthesizing the moment chapter N's synthesis completed — but the user might still be listening to chapter N. When chapter N+1's first sentence arrived, it rebuilt the reading view and stole the player, leaving the audio and text out of sync. Now the next chapter's synthesis and text-swap are deferred until the playerEl 'ended' event fires, so transitions happen at the natural pause between chapters.
  • Cancel-queue cleanup. Hitting the × on the chapter queue pill now fully clears the queue state, so a cancelled queue doesn't flash a misleading "All N chapters synthesized" message later.
v86 Ghost UI elements purged
  • Stale placeholders no longer appear on page load. Nine UI elements (the chapter banner, the queue pill, the URL input row, the mini player, and several others) had CSS display: flex rules that quietly overrode the browser's default behavior for the hidden attribute. So they were visible on every fresh page load, showing whatever placeholder text was hardcoded into the HTML — including a phantom "Chapter 1 of 1" queue pill and a "0 chapters detected" banner that weren't real. Fixed by restoring the spec-defined hidden semantics with one CSS rule. Same class of bug as the v79 Settings dialog regression; regression test added.
v85 Project Gutenberg chapter detection
  • Tom Sawyer (and every other PG book) now splits into chapters. Project Gutenberg wraps chapter titles in HTML that trafilatura was identifying as boilerplate and stripping out — the entire novel arrived as one continuous river of prose with nothing for the chapter detector to grab. The server now BeautifulSoup-parses the raw HTML, pulls h1-h3 tags back out, and re-injects them as markdown ## CHAPTER I markers in front of the matching prose. Works on Project Gutenberg, Standard Ebooks, and anything else with proper heading tags.
  • Chapter title cleanup. Headings that arrive in ALL CAPS ("CHAPTER I") get title-cased to "Chapter I" in the library so the row labels read consistently with the Standard Ebooks bare-numeral path.
v84 Chapter detection for novel-length URL fetches
  • Chapter auto-split now finds chapters in a whole novel. The cap on suggested chapters was 30, which silently swallowed Tom Sawyer (35 chapters) and most other full-length books extracted from URLs — the banner just never appeared. Raised to 200, which covers virtually every novel.
  • Roman-numeral chapter headings get readable titles. Standard Ebooks renders chapter headings as bare Roman numerals ("## I", "## II") instead of the usual "## Chapter 1". The detector now promotes those to "Chapter I" / "Chapter II" so the library cards make sense at a glance.
v83 Illustrations from URL fetches
  • Inline images in the reading view. When you paste a URL with embedded illustrations (Project Gutenberg, Standard Ebooks, a Substack post with a hero image), the pictures now appear between sentences in the reading view as the audio plays. They're stripped from the spoken text so nothing reads "image colon a cat sitting on a fence." Images live with the clip — they survive a save, a reload, and a re-narrate. (Stored as URLs for now; if the source goes down or you go offline, they break gracefully.)
v65 Author — smarter dialogue routing
  • Gender-aware character detection. The Characters dialog now has a He / She / They column. When you've set it, lines with pronoun-only attribution ("How are you?" she asked.) route to the right character even when the named speaker is several sentences back. ~85% accuracy on mixed-gender scenes, up from ~75%.
v62 – v64 Bug fixes + dialogue v1
  • Send feedback works again. The button was silently broken by a URI encoding bug — every alpha tester who tried it just saw nothing happen. Now it opens your default mail app, copies the address to your clipboard as a fallback, and shows a confirmation in the status line.
  • Send feedback (Gmail) → separate link for when your OS default mail app is something you don't actually check.
  • Tier 1 character detection. Paragraph-aware speaker cursor. "He said hello" now correctly attributes when the named speaker ("John walked in.") was in the previous sentence — and the cursor resets at every paragraph break so a new speaker doesn't inherit the old one.
v56 – v61 Voice browser — audition voices on your own text
  • Custom preview text. Paste a sentence from your manuscript above the catalog. Tap ▶ on any voice to hear that sentence in that voice — installed or not.
  • Auditions are temporary. Tapping ▶ on an uninstalled voice installs it just long enough to preview your text. The Install pill turns into a "Keep" button — tap it to commit, or close the dialog and the install auto-reverts. Try voices freely without filling up disk.
  • Language filter. Drop-down above the catalog narrows ~160 voices to just the ones in your language. Each Piper voice only speaks the language it was trained on; this hides the rest.
v53 – v55 Manual rewrite
  • The illustrations in the manual are now real app components, not hand-drawn approximations. They inherit the live theme, update automatically when the app evolves, and won't drift out of date.
  • The page-layout diagram at the top is now a live mini-app with side-callouts explaining what each card is for.
v50 – v52 Author — writing-health signals
  • Filler-word callout — live chip strip below the textarea shows counts of just / very / really / that / kind of etc. Top 8 by frequency. Author mode only.
  • Long-sentence highlighter — sentences over 35 words get a warm amber wash in the reading view, so you can see run-on candidates while you listen back. Author mode only.
  • Voice favorites (★). Star voices you like; they float to the top of the main picker in a "★ Favorites" group, and a "★ Favorites only" filter chip narrows the catalog.
v46 – v49 Reader polish
  • Light theme. Settings → Theme: Auto / Dark / Light. Auto follows your system. Light uses a warm cream palette tuned for daytime / outdoor reading.
  • Chapter auto-split on paste. Paste a book with Chapter N headings (or markdown # Chapter headings) and a banner offers to split it into separate clips. Tap Split, click Generate once, the rest auto-continue in sequence — each chapter saved with its heading as the title.
  • 5-second skip-forward chip — the matching half of the existing ↶5s back. The full pair: ↶5s · 5s↷.
  • Listen stats in Settings. Today / this week / all-time playback time, top voice, most-listened clip. Reset on demand.
v45 Mobile parity
  • Long-press tooltips. Every button with a title attribute (which on desktop appears as a hover hint) now surfaces the same hint on a ~500 ms hold on touch devices. Mobile users finally get the same affordance as desktop.
