v225fz10–fz14 Cover art + chapter banners + figures auto-detected — and previewed before you generate
  • EPUB cover art lands on the library card without asking. The new image-detector ranks EPUB cover lookups in the order Calibre / Apple Books actually use — properties=cover-image first, then the EPUB-2 <meta name="cover"> manifest reference, then a cover.xhtml spine page, then filename heuristics. A matching swatch + Libby-style tint paints onto the card the moment the clip saves (unless you've already uploaded a custom cover — yours always wins).
  • Chapter-leading images surface above sentence 1 in the reading view. A wide, alt-less ornament between <h2> and the first body paragraph renders edge-to-edge as a decorative banner; an alt-bearing or figcaption-bearing image renders as an inline <figure> with the alt text as the caption. The classifier looks at aspect ratio, position, alt-text patterns ("Fig.", "Plate", "Photograph" vs ornament-y silence), and filename hints (ornament, fleuron vs fig01).
  • Inline figures inside the chapter body are no longer silently dropped. EPUB extraction used to call get_text() and lose every <img> tag — so Read Listen Repeat covers, Ex Libris plates, and mid-chapter illustrations vanished. The new extractor walks descendants in document order, anchoring each image to its sentence position and embedding it as a base64 data URL (≤1 MB each). The full set is threaded through to the reading view so figures appear where the author put them.
  • "Detected in this import" preview — see the picks before you spend synth. As soon as the extractor returns, an accent-bordered card lands above the textarea with captioned thumbnails of every image detected — labelled Cover, Banner, Figure, or Inline. Eyeball them, catch the publisher-logo-as-cover or the typeset-page-as- figure, then tap Generate with confidence. Clearing the textarea also clears the preview; importing a new source replaces it.
  • Bug it fixed. EPUBs with a root-level content.opf (Calibre default, also used by A Bicycle Ghost) used to throw "EPUB contains no readable text" because the OPF-directory join produced ./filename instead of filename. Now both the OEBPS-wrapped (Project Gutenberg) and root-OPF (Calibre) conventions extract cleanly.
  • See §3's import table and §10's Tutorial 4 — Upload a file walkthrough for the demo. Sample EPUBs that exercise the full pipeline: Tom Sawyer (gutenberg.org/ebooks/74.epub.images), Huckleberry Finn (43 chapters, 113 images), Alice in Wonderland (Tenniel plates).

v217 Per-voice commercial-use badges — know which voices are safe to publish with
  • Every voice in the browser now carries a license badge. Green "Commercial ✓" means the voice's training dataset license permits selling the audio you generate (with attribution). Amber "Non-commercial" means the license blocks redistribution for profit — fine for personal listening, not for publishing an audiobook.
  • Hover the badge for the credit line. Tooltip shows the dataset, the exact license, the attribution string you'd need to include in audiobook credits, and any nuance worth knowing. (Example: LibriTTS asks you to credit "LibriTTS (Heiga Zen et al.), CC BY 4.0".)

v216 Synth no longer dies when you open the manual / lock the phone / switch apps
  • The v204 watchdog was killing its own synth on mobile. When the synth tab gets backgrounded (manual opens in a new tab, you switch apps, or the phone locks), mobile Chrome / Safari throttle JS execution on the hidden tab — but setTimeout keeps counting against the real clock. The 30s watchdog timer fires while the tab can't process the server's keepalive bytes that would have reset it; the abort() runs on a fetch that the server is happily streaming to; the user returns to a synth that "died" because we killed it.
  • Now visibility-aware. A visibilitychange handler clears the in-flight timer when the tab goes hidden and restarts it with a fresh 30s on visible. Server-side keepalives that piled up while you were away tick the wire as soon as the tab unfreezes, and the watchdog stays quiet through any reasonable away-time.
  • Listener cleanup on every exit path. Removed on done / SSE-error throw / read-rejection catch — chapter queues no longer leak handlers across chapter boundaries.

v214 Dialog headers stay reachable on mobile — dvh fallback added to every dialog
  • The Settings dialog (and several others) used max-height: 90vh with no dvh fallback. On mobile Chrome/Safari where the URL bar is visible, vh measures the largest viewport (URL bar collapsed) — so a 90vh dialog overflows the visible area and its centered position pushes the top edge — including the Close button — off-screen.
  • Added dvh fallback to every dialog max-height. Settings, Voice browser, Characters, Document picker (GitHub / Scrivener / Obsidian), All bookmarks, Book-view Contents — all now use max-height: 85vh; max-height: 85dvh; (or their respective value). dvh follows the current viewport, so when the URL bar is showing the dialog shrinks to fit visibly.
  • Same fix on the small-phone full-screen rules. Settings / Characters / Voice browser at ≤480px viewports use height: 100vh for full-screen presentation. That hid the bottom slice on mobile too. Now uses 100dvh as well.
v213 Library + Voice dialogs now actually scroll when content overflows
  • Long libraries lost their scrollbar. The dialogs had max-height: calc(100vh - 48px) and display: flex, but no explicit height. The inner scroll container's height: 100% can't resolve against a max-height-only parent — so the dialog grew to its content size, hit the cap, clipped silently via overflow: hidden, and never engaged the inner overflow-y: auto scroll region.
  • Two-line fix. Added an explicit height on both .library-dialog[open] and .voice-dialog[open] — matching the existing max-height in modal mode, and full 100dvh at desktop drawer mode. The v156 "swap-to-focus stack" rules retain higher specificity (selector chains 4 deep) so the stack behavior when both drawers are open is preserved.

v207 Book view M5: trailing images get their own pages + magazine-aware image sizing
  • M5.2: trailing images paginate properly now. Previously the renderer just dumped every trailing image (sentence_index past the last sentence) onto the last text page with no overflow check — a chapter with many or oversize trailing figures would silently clip. v207 adds a post-sentence pagination pass that measures each trailing image, fits it on the current page first, and spills to fresh trailing pages on overflow. Per-page buckets live on _bookViewSource.trailingByPage so the renderer just looks them up by page index.
  • M5.3: small images stay inside a column in magazine. The default is column-span: all (image spans both columns) which suits chapter-opening figures. v207 marks small images (natural width < one column) with data-single-col and CSS skips the column-span — the image renders inside whichever column it landed in. v206 Book view M4: chapter awareness — drop caps, running headers, table of contents
  • Chapter detection at the sentence level. _bookViewDetectChapters() scans the clip's sentences for Markdown #/##/### headings, "Chapter N" / "Part Three" patterns, and bare Roman numerals as short standalone sentences. Returns [{sentence_index, title}] stashed on _bookViewSource.chapters for the renderer + paginator + TOC.
  • Chapter-aware drop caps. The drop cap now fires on the first text page of every detected chapter, not just page 1 of the clip. Falls back to page-1-only when no chapters are detected (single-clip mode).
  • Chapter-aware running headers. Each page's header shows the title of the chapter that contains its first sentence. Pages before the first detected chapter (preamble) fall back to the clip title. Clips with no detected chapters work exactly as before.
  • 📑 Contents button + dialog. New nav button (hidden when no chapters detected) opens a dialog listing every chapter with its computed page number. Click a row to jump to that spread — routes through the same _bookViewNavigateManual path as the prev/next buttons, so the pinned-scrub state flips correctly.
  • Paginator forces a page break before each chapter. Each chapter opens on a fresh page — book convention. Previously a chapter could start mid-page if the preceding chapter ended with room to spare.
v205 Clear button now also stops the audio + hides the player
  • The Clear button decouples everything from the previous clip now — audio included. Previously Clear emptied the textarea, cancelled the chapter queue, and reset the Save Text wiring, but left the player card visible and the audio playing. Felt wrong — workspace looked fresh but the previous clip kept narrating. v205 pauses playback (via _pauseAsUser() so the sleep/interruption trackers stay consistent) and hides the player card.
v204 SSE keepalive (server) + watchdog (client) — no more silent hangs on long synth jobs
  • Server emits keepalive comments. A new _sse_with_keepalive() helper wraps both /api/synthesize/stream and /api/synthesize/segments/stream. If the underlying Piper iterator hasn't yielded a sentence event in 15 s, the wrapper emits : keepalive\n\n (an SSE comment line — EventSource clients ignore them per the spec, but every byte counts as response traffic to intermediaries). Fly's autostopper, nginx, Cloudflare — all see continuous bytes and don't decide the connection is dead.
  • Client watchdog on the bg-synth reader. _preSynthesizeChapter()'s SSE read loop now resets a 30 s timer on every reader.read() return (including server keepalive bytes). If 30 s pass without ANY bytes — server crashed / network died / proxy killed the connection — the watchdog fires myController.abort(), the read rejects, the catch block re-throws as "connection lost — server may be restarting or unreachable", and the existing 1.5 s retry path engages. 30 s is 2× slack against the server's 15 s keepalive cadence.
  • Together: no silent hangs. The scenario from 2026-05-30 (phone synth job stuck for 11+ minutes because Fly autostopped the machine mid-stream and the client kept waiting on a dead TCP socket) now surfaces as a clear failure within 30 s, retries once, and lands in the existing "needs a retry" banner if both attempts fail.
v202 Book view M3.3: print the entire book — one page per sheet
  • 🖨 Print button in the book-view nav. Renders the full clip (cover + every text page) as a stack of paperback-sized printed sheets. Use the browser's print dialog to save as PDF or send to a real printer.
  • One page per sheet. The print path re-renders the spread as a flat sequence of .book-page elements, each marked with page-break-after: always. The current theme, font size, drop cap, running header, and page numbers all carry through to print. Inline images print at their preloaded sizing.

  • State restoration. When you close the print dialog (confirm OR cancel), the book view restores the single-spread view you were on. Click- to-seek, karaoke, and the floating chip strip all resume operating on the right DOM nodes.
  • Print-friendly colour stripping. The @media print rules force black text on white backgrounds for the body, mute the accent to a dark grey for the drop cap, and hide the gutter shadow + binding line so the print doesn't look like a screen screenshot.

v201 Book view M5.1: paginator now catches magazine 2-column overflow
  • Magazine pages were silently overflowing. The v199 paginator only checked vertical overflow via body.scrollHeight > pageHeight. That works for paperback / manuscript (single-column) where the body grows past its flex allocation when content's too tall. But CSS multi-column with column-fill: auto inside a fixed-height flex child overflows horizontally — content past the last column extends to the right of the body. scrollHeight stays at clientHeight, so the old check never fired in magazine mode and the paginator packed every sentence onto page 1 (visually clipped by overflow: hidden).
  • Hybrid overflow predicate. v201 extracts _bookViewBodyOverflows() that returns true on EITHER vertical (scrollHeight > pageHeight − 1) OR horizontal (scrollWidth > clientWidth + 1) overflow. Magazine theme now paginates correctly into multiple spreads. Paperback / manuscript behavior unchanged — the vertical branch still fires first.
v200 Book view M3.2: inline images, paginated alongside the prose
  • Images from URL-imported chapters now appear in the book view too. The reading view has rendered them inline since v85; the book view caught up in v200. Each image is anchored to its sentence_index (the position the trafilatura extractor recorded) and renders just before that sentence — same semantics as the reading view.
  • Image-aware paginator. Before pagination, every image's natural dimensions get preloaded via new Image() so the off-screen measurement probe can reserve the right amount of vertical space before the network finishes the actual download. Each image + its anchor sentence are treated as an atomic unit — if the pair doesn't fit on the current page, both move to the next. An image never separates from the sentence it introduces.
  • Centered, capped at half-page-height. Inline images sit centered with max-height: 50% so a single photo can't dominate a page. Magazine 2-column body lets images span the gutter via column-span: all — they break the column grid and read like full-width figures.
  • Caches across repagination. The bucketed image map + dimension cache stash on _bookViewSource, so switching theme or text size doesn't re-download anything — paginator just re-runs against the same memoized data.

Still pending in M3: print stylesheet for a "Print spread" affordance that breaks at page boundaries.

v199 Book view M3: three theme variants — Paperback, Magazine, Manuscript
  • New Settings row: Book view theme. Pick the typographic personality of book pages independently from the app-wide Dark/Light theme.
  • Paperback (default). The existing serif single-column layout — Iowan Old Style with justified text and tight letter-spacing.
  • Magazine. Sans-serif (Inter / Helvetica Neue stack), tighter line-height, two columns on desktop. On phones it collapses to a single column since two ~140px columns are unreadable.
  • Manuscript. Monospace (Courier Prime), looser line-height, left-aligned (no justification) — the typewritten-draft look. No italic by default; the wider line does the work.
  • CSS custom properties throughout. Every typographic dimension on .book-page-body (font-family, line-height, letter-spacing, text-align, column-count) now reads from a --book-* var. Themes override the vars via a data-book-theme attribute. The off-screen paginator probe carries the same attribute so measurement metrics match the live render — otherwise switching themes mid-clip would paginate against paperback metrics and visibly overflow in magazine.

Caveat: Magazine's CSS multi-column inside a flex child relies on browser-specific scrollHeight semantics for overflow detection. If pages crowd or come out short, that's the paginator under multi-column — file feedback and I'll switch to a horizontal-overflow check.

  • v87's chapter-queue fix had a race condition. Some inputs (notably those starting with non-speech punctuation like "|| July 2024" or "[1]") caused Piper's WAV writer to skip the channel-count header, which then made the whole synthesis blow up with a cryptic "# channels not specified" error. The wave file now gets pre-initialized with valid mono defaults so even no-audio outputs produce a well-formed WAV, and any sentence that still fails falls back to silence so the rest of the chapter still synthesizes. Verified end-to-end on the Paul Graham "Persistence and Obstinacy" essay that triggered the bug — 14 sentences, 2.7 MB combined WAV, 502 KB MP3, zero errors.
v88 Clearer errors during server cold start
  • Generate now fails fast when no voice is selected. Clicking Generate with an empty voice dropdown used to route through to the SAPI fallback, produce a malformed WAV, and surface the worst error message in the app — "mp3 encode failed". Now it says "Pick a voice first — the dropdown is empty" before any of that runs.
  • Voice catalog auto-retries on 503. The usual cause for an empty voice dropdown is the server still waking up (Fly.io cold-start, slow first import). The app now shows "Server is waking up — retrying in 10s…" and keeps trying until the catalog loads. No more silent empty dropdown + baffling encode error.
v87 Chapter queue stays in sync with playback
  • Chapter auto-advance now waits for the audio to actually finish. Previously, chapter N+1 started synthesizing the moment chapter N's synthesis completed — but the user might still be listening to chapter N. When chapter N+1's first sentence arrived, it rebuilt the reading view and stole the player, leaving the audio and text out of sync. Now the next chapter's synthesis and text-swap are deferred until the playerEl 'ended' event fires, so transitions happen at the natural pause between chapters.
  • Cancel-queue cleanup. Hitting the × on the chapter queue pill now fully clears the queue state, so a cancelled queue doesn't flash a misleading "All N chapters synthesized" message later.
v86 Ghost UI elements purged
  • Stale placeholders no longer appear on page load. Nine UI elements (the chapter banner, the queue pill, the URL input row, the mini player, and several others) had CSS display: flex rules that quietly overrode the browser's default behavior for the hidden attribute. So they were visible on every fresh page load, showing whatever placeholder text was hardcoded into the HTML — including a phantom "Chapter 1 of 1" queue pill and a "0 chapters detected" banner that weren't real. Fixed by restoring the spec-defined hidden semantics with one CSS rule. Same class of bug as the v79 Settings dialog regression; regression test added.
v85 Project Gutenberg chapter detection
  • Tom Sawyer (and every other PG book) now splits into chapters. Project Gutenberg wraps chapter titles in HTML that trafilatura was identifying as boilerplate and stripping out — the entire novel arrived as one continuous river of prose with nothing for the chapter detector to grab. The server now BeautifulSoup-parses the raw HTML, pulls h1-h3 tags back out, and re-injects them as markdown ## CHAPTER I markers in front of the matching prose. Works on Project Gutenberg, Standard Ebooks, and anything else with proper heading tags.
  • Chapter title cleanup. Headings that arrive in ALL CAPS ("CHAPTER I") get title-cased to "Chapter I" in the library so the row labels read consistently with the Standard Ebooks bare-numeral path.
v84 Chapter detection for novel-length URL fetches
  • Chapter auto-split now finds chapters in a whole novel. The cap on suggested chapters was 30, which silently swallowed Tom Sawyer (35 chapters) and most other full-length books extracted from URLs — the banner just never appeared. Raised to 200, which covers virtually every novel.
  • Roman-numeral chapter headings get readable titles. Standard Ebooks renders chapter headings as bare Roman numerals ("## I", "## II") instead of the usual "## Chapter 1". The detector now promotes those to "Chapter I" / "Chapter II" so the library cards make sense at a glance.
v83 Illustrations from URL fetches
  • Inline images in the reading view. When you paste a URL with embedded illustrations (Project Gutenberg, Standard Ebooks, a Substack post with a hero image), the pictures now appear between sentences in the reading view as the audio plays. They're stripped from the spoken text so nothing reads "image colon a cat sitting on a fence." Images live with the clip — they survive a save, a reload, and a re-narrate. (Stored as URLs for now; if the source goes down or you go offline, they break gracefully.)
